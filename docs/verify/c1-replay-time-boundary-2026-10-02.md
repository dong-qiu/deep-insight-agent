# C1 恢复时间边界：阻塞项复现

## 状态

PR #388 已于 2026-10-02 合入 `d66883df1198398a84b2e365334707ef6fbc13c9`。本轮未部署生产、未读取生产数据或云登记册，未完成服务恢复验收。TD-09 仍为 incomplete。

推进合成演练时发现：`generation-provenance.md` §7 同时要求覆盖“恢复点早于删除”，又要求 `effective_at <= restore_time < expiry_at`。当 restore_time 是备份快照时间时，这两个要求冲突。运维手册的恢复示例也明确把该参数当作目标恢复点。

## 离线证据

`ops/replay-redaction-boundary.node-test.mjs` 执行真实 runner、AES-GCM/HMAC 和 SQLite，仅在构建时替换 AWS 客户端 transport。合成 key 随机生成、仅在临时目录存储并清理；子进程使用显式环境，不继承 AWS/LLM 凭据。没有真实 AWS SDK 网络行为、IAM 或同镜像服务验证。

| 输入 | 实测结果 |
| --- | --- |
| 删除登记 10 月 1 日；restore-time 为 10 月 2 日 | 退出 0，应用 1 条；重复运行后库内仍为 1 条 |
| 同一登记；restore-time 为 9 月 30 日 | **退出 0，records_seen=1，但 records_applied=0，库内 tombstone=0** |
| 可入选记录的 HMAC 错误 | 非零退出，未写 tombstone，无成功事件 |
| 可入选记录缺少密钥版本映射 | 非零退出，未写 tombstone，无成功事件 |
| transport 失败 | 非零退出，未创建 DB/WAL/SHM，无成功事件 |

这是一组**现状刻画测试**，通过不代表恢复安全通过：早于删除的时间输入被静默跳过，仍输出成功事件。这阻塞后续“replay 成功即可启动”的验收。测试没有装载真实或合成备份报告，没有证明 HTTP 可读取已删除报告；证明范围是时间筛选与本地 tombstone 落库。

验证：上述 Node 测试 6/6（含父测试），与前置检查联跑 12/12；TS6/TS7 类型检查、对应文件 eslint 和 diff 空白检查通过。本地 Node 25，非目标 Node 24 容器证据。

## 建议修复顺序（尚未实现）

1. 修订 spec 与恢复命令契约：明确区分快照时间和恢复执行的安全截止时间，不能用快照时间排除后续删除。明确截止时间来源、UTC 规范化与未来时间拒绝规则。
2. 对有效删除记录回放，并确定过期登记对仍可恢复的长期备份如何处理。保留现有版本化备份、不要求所有版本 90 天删除的前提下，不能仅凭登记过期就推断旧备份安全；需保留足够的删除记录/密钥，或对覆盖不足的快照拒绝恢复。
3. 将本测试的 KNOWN GAP 改为安全回归断言，补充边界时间、过期/未来记录、混合有效与坏签名记录的原子性，以及全量读取覆盖不足时的拒绝场景。不要把现状刻画断言当成目标行为保留。
4. 再完成新格式备份校验、成功回放、认证轮换与 HTTP/删除对象不可见验收；只有恢复安全门闭合后才启动服务。

本轮不改生产 runner、过期策略或历史数据，不通过把 restore-time 随意改成当前时间来掩盖契约冲突。
