# C1 / TD-09 生产备份与异地副本核验（2026-10-01）

## 结论与边界

**备份机制和异地传输已得到生产实证，但尚无可宣称“完整恢复”的恢复点；TD-09 继续保持部分完成。**
2026-09-30 的本地备份与从 S3 下载的隔离副本，清单、文件哈希和 SQLite 自检结果一致；两者均因历史数据库引用缺口返回 `references_incomplete`。本次没有改写生产数据库、报告或原文，也没有执行生产恢复或脱敏登记册回放。现时来源网页和重新抓取不能补作生成时原文字节。

核验时生产 `cron` 镜像的 OCI revision 为 `b3d67d78f0a441be5c16f86ea78b6eeea992f406`，镜像 digest 为 `sha256:94e5c2db462e0dfa57d61f404d3cd72de6f849d7f3b3a523024a32a865f74c76`。所有数据检查都针对已封存备份或隔离副本，不连接 live SQLite。

隔离校验首次以镜像默认 `app` 用户运行时返回 `manifest_missing`；原因是 `mktemp -d` 建立的宿主临时目录权限为 `0700 root`，并非 S3 缺清单。宿主检查确认清单存在；第二次以容器 root 用户、保持断网和只读挂载重新校验，得到上述与本地完全一致的结果。不能把首次权限错误记成备份损坏。

SSM 核验与临时副本清理命令收据：生产盘点 `812caa7f-a782-49ec-b60f-0b66a94a8ce2`、清单摘要 `f0e2bfed-d1fb-4004-a25d-e3bc544b5912`、本地核验 `20d177a9-9ab8-46d3-8a17-82afeab977f2`、隔离核验 `a0259bbf-0481-448f-b8ac-f7bed34dc03e`、临时副本清理 `d5349905-6a31-4914-87fd-0e5aafff9437`。记录只含聚合计数和版本，不包含原文、凭据或个人数据。

## 未收口项

1. 415 个缺文件引用和 1,808 个无法映射引用必须依备份 DB 与历史证据逐类核对。此前盘点已有旧 `.data/raw/` 路径、空 `raw_ref`、缺失原文与早期报告正文；不能仅凭数字相加就断言所有缺口的最终类别或可恢复性。
2. 若能从仍在保留窗口内的旧原始归档找回**同一原字节**，须另行制定只读比对和受控恢复方案；找不到时须明确标记历史不可恢复范围，并决定产品层面的历史例外。不得静默回填、重新抓取或把 `incomplete` 改称 `complete`。
3. 本次隔离演练证明 S3 对象可取回且与清单/备份 DB 一致，**不等于**整套生产服务恢复、脱敏登记册回放与业务可读性演练。真正恢复仍按 [运维手册](../launch/operations.md#61-自动备份默认开无需配置) 停止写者、校验恢复点、回放登记册并通过身份与健康门。

因此，C1 的“生产备份与异地副本证据”已收集并明确失败边界；[TD-09 验收标准](../plan/specs/backup-recovery-integrity.md)中“完整恢复点”不能勾选，直至历史缺口处置与完整隔离恢复验收完成。
