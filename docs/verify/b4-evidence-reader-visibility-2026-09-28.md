## 功能验证

- 临时 SQLite + 临时归档的接受/拒绝测试覆盖：v1 正例、当前内容缺失、pending 替换、缺失/损坏归档、正文改写但 quote 仍在、纯原文归档、旧 unknown 后有新 committed、manifest 漂移及正文 hash 漂移。
- 图谱节点/边/下钻、线索列表/详情、机会过滤、离线合格线索导出共用当前证据门；旧测试夹具升级为真实归档，不保留测试专用放行旁路。
- Lead/Opportunity GET 路由在隔离实库与真实 v1 归档上做生产等价集成：合格证据返回 200，归档损坏后两个路由均返回 404；路由单测另核对一个请求复用同一证据 context。
- 机会列表的批量查询与单条查询共用同一 SQL、v6 审计和当前归档门；真实合格/无证据混合线索跨 400-ID 分块与单条结果一致。图谱下钻预筛与最终过滤使用同一实体匹配规则，未跳过入选洞察的验真。
- 图谱 HTTP E2E 夹具也写入真实 v1 归档与 committed effect；登录后下钻仍保留两条原始 occurrence 及报告链接。首次 PR CI 暴露旧夹具只有洞察而无 ContentItem/归档，严格门正确返回空集合；补齐夹具后 `npm run test:e2e` 6/6 通过，不为测试设置放行旁路。
- 管理员历史复盘每次展示前重新核对 `content-v4` 白名单、revision 和 `snapshot_hash`；仅展示历史元数据并说明历史原文字节不可由此核验。
- `npm test`：222 个 Vitest 文件、2220 项测试及 33 个 ops 测试通过；`npm run typecheck`（TS 7/6）、`npm run lint` 和 `npm run build` 通过，均使用仓库要求的 Node 24.19.0。
- Eval-Gate：scoped（读者侧证据准入的真实 DB/API/图谱回归及同快照实际读取函数对照；A1 不执行 B4 代码路径，不作为本次质量证明）。
