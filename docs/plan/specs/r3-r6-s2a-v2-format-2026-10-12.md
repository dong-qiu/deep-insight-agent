## 初始化与物理 marker

复用 S0 `isolation.json`/`ledger.sqlite` 的现格式与 `openLedger`，先由现 S0 initializer 在真正新空 root 创建。S0 固定 target 推荐 instanceId=`fixture-writers-v2-node`、volumeId=`fixture-writers-v2-volume`、serviceSet=[`fixture-writers-v2`]、region=`isolated`、dataPath=root；合法现 contract，无新 S0 token 格式。旧 controller 的 fixture-controller profile 不匹配，因此拒绝该控制 action；S0 通用 ledger/CLI 仍能操作 S0 事实，不能说它们检查或关闭 v2 writer。

新 writer 使用相同排他 filenames `writers-isolation.json`、`writers.sqlite`。推荐新 APP_ID **`0x41335732`**，user_version **2**（旧 `0x41335731`/1 保留），减少只检查 APP_ID 的误接受；reader 必须同时验证 marker、APP_ID、version、全 sqlite_master 与所有行。未知/混合任意一项直接拒绝，不写 migration/repair、不 fallback。不是复用旧 ID；若主控另选复用 ID，须重新列误接受消费者后冻结。

marker 是 UTF-8 canonical JSON 加单个 LF，strict own data properties，exact keys：

```json
{"schema":"a3-writers-isolation-v2","initId":"UUID","ledgerMarkerHash":"SHA256","root":{"path":"CANONICAL_ROOT","dev":"DECIMAL","ino":"DECIMAL"},"registry":{"name":"writers.sqlite","dev":"DECIMAL","ino":"DECIMAL"},"targets":{"business":"d2-business.sqlite","raw":"raw","report":"report"}}
```

dev/ino 为非负规范十进制字符串，UUID、SHA256 严格验证；ledgerMarkerHash 是现 S0 marker 的 canonical JSON（无 LF）的 SHA256。marker root/registry 身份冻结，marker 文件自身 dev/ino 由每次 open 的 private connection binding 固定并重查。不得接 path override、DB handle、dynamic env、accessor/Proxy。root canonical/no symlink/uid/mode0700；marker/registry 普通文件、nlink=1、uid、mode0600；受控目录逐层 no symlink、same root，创建前核 parent、创建后核 inode。每次 consumption 重查 root/marker/registry/目标，不仅第一次打开。

初始化前 root 仅允许已核 S0 两文件及其合法 DELETE journal；writers marker/sqlite、旧 fixture-business、raw/report/business、stage 文件任何既存均拒绝。SQLite WAL/SHM、symlink/hardlink/不明 sidecar 拒绝；S0 可能自身恢复，不能把检查称零副作用。初始化先 O_EXCL registry 占位取得 inode，再 O_EXCL marker，fsync 文件/目录，然后 SQLite 建表、identity/admission/audit 初始事务与 FULL COMMIT；所有步骤同步，0跨 await。open 先物理/marker检查才 writable SQLite constructor，可能产生的 hot-journal 恢复单独记事实。中途任意失败保存文件与 unknown/incomplete，不删除重试；不完整 marker/DDL/identity 永久拒绝正常 open。重新新 root 需要独立目标授权，不能“修残留”开门。

`d2-business.sqlite` 未创建时没有 inode，不写假的绑定；pre-open 固定消费者在 registry 锁内 O_EXCL 创建、constructor、必要同步配置，实际 inode/连接绑定写 bindings。若业务文件已创建而 binding ACK 不确定，保存文件与 consumed step，拒绝普通重试，由 fresh recovery 诊断；不以 O_EXCL 碰撞认定原效果未发生。raw/report 目录在对应固定消费中创建，逐目录 binding；不在 registry 初始化偷偷生成业务产物。

## exact sqlite_master 提案

下面为新 registry 的 exact table SQL（实现SQL去除末尾分号，以SQLite存入sqlite_master的文本逐字比对；保持顺序、空格，SQLite自建索引也核名字/列）。不使用 AUTOINCREMENT，foreign_keys=ON、DELETE/FULL，无 WAL。UUID/hash/entry/step 与跨行语义由固定 parse/全行 validateRows 复核，DDL 不替代身份验证。

```sql
CREATE TABLE identity (id INTEGER PRIMARY KEY CHECK(id=1), marker TEXT NOT NULL);
CREATE TABLE admission (id INTEGER PRIMARY KEY CHECK(id=1), mode TEXT NOT NULL CHECK(mode IN ('open','closed')));
CREATE TABLE workers (worker_id TEXT PRIMARY KEY, generation_token TEXT UNIQUE NOT NULL, entry_point TEXT NOT NULL CHECK(entry_point IN ('generation-dispatch','source-collect','startup','local-seed','raw-recovery','report-recovery')));
CREATE TABLE tasks (task_id TEXT PRIMARY KEY, worker_id TEXT NOT NULL REFERENCES workers(worker_id));
CREATE TABLE operations (operation_id TEXT PRIMARY KEY, task_id TEXT UNIQUE NOT NULL REFERENCES tasks(task_id), invocation_id TEXT UNIQUE NOT NULL, scope_json TEXT NOT NULL, input_hash TEXT NOT NULL, recovery_of TEXT);
CREATE TABLE steps (step_id TEXT PRIMARY KEY, operation_id TEXT NOT NULL REFERENCES operations(operation_id), step_key TEXT NOT NULL, ordinal INTEGER NOT NULL CHECK(ordinal>=0), input_hash TEXT NOT NULL, UNIQUE(operation_id,ordinal));
CREATE TABLE bindings (step_id TEXT PRIMARY KEY REFERENCES steps(step_id), target_kind TEXT NOT NULL CHECK(target_kind IN ('business','raw','report')), identity_json TEXT NOT NULL);
CREATE TABLE step_results (step_id TEXT PRIMARY KEY REFERENCES steps(step_id), business_commit TEXT NOT NULL CHECK(business_commit IN ('not_committed','committed','unknown','not_applicable')), filesystem_json TEXT NOT NULL, disposition TEXT NOT NULL CHECK(disposition IN ('completed','denied','cancelled','unsupported','unknown')), reason TEXT NOT NULL);
CREATE TABLE terminals (operation_id TEXT PRIMARY KEY REFERENCES operations(operation_id), outcome TEXT NOT NULL CHECK(outcome IN ('completed','completed_with_diagnostics','denied','cancelled','interrupted_unknown')), first_reason TEXT NOT NULL);
CREATE TABLE audit_facts (seq INTEGER PRIMARY KEY, previous_hash TEXT NOT NULL, hash TEXT UNIQUE NOT NULL, fact_json TEXT NOT NULL);
```

exact trigger inventory：每个 identity/workers/tasks/operations/steps/bindings/step_results/terminals/audit_facts 表各两个，名字为 `<table>_no_update`、`<table>_no_delete`，SQL 模板（替换 table/name 后展开为 exact strings）：

```sql
CREATE TRIGGER <table>_no_update BEFORE UPDATE ON <table> BEGIN SELECT RAISE(ABORT,'writer_v2_facts_append_only'); END;
CREATE TRIGGER <table>_no_delete BEFORE DELETE ON <table> BEGIN SELECT RAISE(ABORT,'writer_v2_facts_append_only'); END;
CREATE TRIGGER admission_no_delete BEFORE DELETE ON admission BEGIN SELECT RAISE(ABORT,'writer_v2_admission_permanent'); END;
CREATE TRIGGER admission_no_reopen BEFORE UPDATE ON admission WHEN OLD.mode='closed' BEGIN SELECT RAISE(ABORT,'writer_v2_admission_permanent'); END;
```

exact counts：10 tables、20 triggers；SQLite 自动唯一索引逐表按上述 PK/UNIQUE 派生，允许名单由实现常量展开后冻结，拒绝额外 table/view/index/trigger。identity/admission 各恰好一行；closed 不能 UPDATE 成 closed，以只读观察处理重复关闭；admission 除 open→closed 外不准写。audit seq 连续从1开始，genesis previous_hash 为64个0；hash=SHA256(canonical({seq,previousHash,fact}))，fact_json 为 canonical discriminated facts：initialized/registered/admitted/step_reserved/step_result/terminal/closed；每事实与对应行在同 registry 事务插入并全行交叉核对，closed 唯一且 admission closed 相匹配。不用 audit timestamp/PID 作为权威。

S2a JSON载荷与audit双向覆盖冻结如下（表中的key全部必需，无额外key；JSON都canonical、普通自有data descriptor；整数为safe nonnegative，id/UUID/hash按对应row验证）。不能只校验链hash或fact指向某行。

| fact.kind | exact payload keys（含kind）与唯一覆盖行 |
| --- | --- |
| initialized | `{kind, marker}`，marker为identity.marker原canonical字符串；仅seq1，覆盖唯一identity及初始admission=open |
| registered | `{kind, workerId, generationToken, entryPoint}`，覆盖该唯一workers整行 |
| admitted | `{kind, taskId, workerId, operationId, invocationId, scopeJson, inputHash, recoveryOf}`，覆盖tasks及operations两整行；scopeJson是canonical字符串，recoveryOf=null或非空规范effect引用 |
| step_reserved | `{kind, stepId, operationId, stepKey, ordinal, inputHash}`，覆盖steps整行 |
| step_result | `{kind, stepId, businessCommit, filesystemJson, disposition, reason, binding}`，覆盖step_results整行；binding为null或`{targetKind, identityJson}`，非null时同时覆盖bindings该step整行 |
| terminal | `{kind, operationId, outcome, firstReason}`，覆盖terminals整行，不代表startup/report已接线或全writer完成 |
| closed | `{kind, previousMode, nextMode}`，只允许open→closed，覆盖admission最终变化；全库至多一次，重复close只观察不追加 |

identityJson exact keys为`{path, dev, ino, parent:{path, dev, ino}, creation}`；creation=new/existing；所有路径必须固定受控target或其已冻结目录，dev/ino规范字符串；binding.targetKind与step、入口及实际FS身份匹配。S2a仅open-business的business binding，raw/report尚unsupported；已有文件只有真实同registry确定committed且identity验证的旧binding可作为existing依据，缺失/unknown不得普通open，需fresh诊断（未实现时拒绝）。业务connection只在WeakMap，不进identityJson。filesystemJson是canonical数组，元素exact `{action, path, outcome}`：S2a action=create/open/configure，outcome=occurred/not_occurred/unknown；路径只为d2-business或已核SQLite合法sidecar。FS未发生为空；打开与配置可能有sidecar效应，实际发生/无法确定分别记录，不借not_applicable SQL假称FS零。raw/report mkdir/rename载荷和domainsteps到S2b/A/P另冻，S2a拒绝未知action。

binding与step_result及其audit在同一个registry ACK事务内提交，不独立新增binding audit；ACKunknown可表现仅reservation、或ACK三者已持久，open全行检验决定事实而非caller假定。每条workers/tasks/operations/steps/results/bindings/terminals必须恰好被上表对应fact覆盖一次；反向每个fact必须有匹配整行，不允许orphan/缺失/重复/未审计行。binding非null与对应行存在双向等价，step_result为null binding时不存在该binding；不同open的business身份必须一致。admission closed恰好有closed fact，open没有；audit kind与序数/行状态先后必须符合初始化→register→admit→reserve→result→terminal，closed可穿插后续合法诊断/收尾，但closed后不新增workers/tasks/operations/消费reservation。

合法未ACK状态只包括steps已有reservation而无result/binding，返回unknown、无执行权；terminal不得completed覆盖这种未知或发生拒绝/取消/unknown的step。每operation的第n+1reservation只能在前n已确定合法completed并业务+协调结果确定后插入；no-op明确not_applicable，不能称COMMIT。没有domain consumer的登记可用于inventory探针，finish只能denied或cancelled，不把登记成功写成domain completed。实际S2a pre-open-only完成也只是打开阶段结果，不签startup整体完成。恢复terminal/fact不更新旧unknown，使用fresh任务链接旧effect。

负例验收：链hash正确但worker/task/step/result/binding缺失、重复、额外行、binding与identityJson或result不一致；closed事实与admission不一致；旧worker SQL重建；结果ACK丢失但FS已create；这些必须拒绝或保留reservation unknown，而非修库/补事实。SQLite唯一索引exact名单：workers_1(worker_id)、workers_2(generation_token)、tasks_1(task_id)、operations_1(operation_id)、operations_2(task_id)、operations_3(invocation_id)、steps_1(step_id)、steps_2(operation_id,ordinal)、bindings_1(step_id)、step_results_1(step_id)、terminals_1(operation_id)、audit_facts_1(hash)，名称均加`sqlite_autoindex_`前缀，共12，sql=NULL；实现需核index_list/index_info与真实schema，任何差异先回主控，不放宽接受。

`operations.recovery_of` 仅为可核旧 effect 的引用，不是 registry operation FK（可能来自业务 effect）；fresh recovery 自己 task/invocation，不改旧 operation。scope_json strict按 entry 的固定值 schema：dispatch 六字段；source prelude sourceId/triggerKind/scopeKey/retry provenance（无伪 rootRunId）；startup 配置/版本摘要；local-seed 静态 config摘要且local-only；recovery effectId/kind/idempotency/manifest/input摘要。raw/report 文件/业务绑定为 bindings 数据，SQL fact 不存 handle 或 capability。source root-bind 是七字段 `traceId/sourceId/scopeKey/activeKey/ownerToken/fencingEpoch/rootRunId`，从同一真实连接的 trace/lease/Run 读出并重查 source/scope/activeKey/root，不凭旧三字段 SourceCollectClaim 补造；在S2b另冻固定step的input/fact，不 UPDATE 原prelude scope。

steps 是**持久单次 reservation**，不是可执行许可。每 operation ordinal 单调、step_key 固定入口白名单及合法状态机（S2b 实施前先冻结全部 domain step 值）；S2a计划只实现 `open-business`（仅startup/local-seed可消费，其他entry拒绝该step），其他只支持登记/inspect/拒绝，不持久预留“未来可用”cap。旧 task、clone、inspect SQL值不恢复 cap；WeakMap 原对象、代际、固定 consumer 与同一 DB handle 才能消费。重复 invocation/scope 冲突无新权限。reservation COMMIT unknown 时不运行后续 business effect；无 result/terminal 是 unknown，不当 completed。下一阶段只在确定上一阶段结果与协调 ACK、仍 owned 时发放。

## 固定 API 和取消/COMMIT 合同

`initializeWritersV2(root)` 只接一个 canonical root primitive，S0 配置已固定；返回只读格式身份。`openWritersV2(root)` 只在完整 v2 物理/版本/行验证后返回 private registry handle。methods 为 `register(workerId, entryPoint)`、`admit(worker, frozenScope, signal)`、`inspect()`、`closeAdmission()`、`finish(operation, outcome)`、`close()`；entryPoint enum 不是任意 callback。register返回本handle WeakMap原worker cap，admit只接受该原worker、原generation且同一registry handle；持久worker/token/clone或重新open不能复活它。admit 返回 WeakMap 原对象 operation cap，不输出可重建 cap 的 SQL token；public inspect 返回持久事实及 observed unknown。register/admit 首先检查 open，finish 是记录已有事实、允许关闭后收尾但不追加业务权限；finish unknown 保留首因，冲突拒绝，重复同结果只读幂等。

`admit` 的第三参数 signal 为**必需原 AbortSignal 对象**，由可信调用方为该invocation创建或传入；不允许undefined/布尔快照/结构相似对象/Proxy/accessor。固定factory通过native AbortSignal getter brand检查及node:util.types.isProxy拒绝代理，不读取caller自定义aborted属性；原对象只存private WeakMap，后续不可替换。signal不进入scope_json/input_hash/audit，不从SQL重建；检查aborted使用原native getter，首因由cap记录，持久结果只保留规范取消reason。initialize/open/register/inspect/control-close不接signal：它们只建立或观察协调事实，不发business消费；cancelled信号admit返回拒绝而无task/operation。所有business消费必须来自绑定signal的operation。

pre-open取消时序：admit前已取消不登记operation；reservation前取消返回not_committed/cancelled且不做FS，cap消耗；reservation确定commit后、重新取锁消费前取消，保留reservation并追加cancelled step_result（business_commit=not_applicable、FS空），0mkdir/constructor。窗口内每个FS动作前及业务COMMIT前再查原signal；已有create/open后取消保留occurred FS与真实SQL三态，不能写成零效应。业务COMMIT正常返回后的迟到取消保持committed；ACK失败照样coordination_unknown，finish保留首因，无退款/清零。跨进程取消只能用真正close/lease协议，不以本进程signal替代close。

固定 runtime factory `openV2Business(operation)` 位于 writer-admission-v2.ts，内部固定 path/SQLite constructor与配置；无 driver、SQL、callback 参数。返回本地 DB handle 与 private binding供后续固定 consumer，不发布 `_db`、不包围整个 legacy bootstrap。S2a fixture 只检空库/句柄/FS配置事实，不创建业务 schema。S2b 用明确 domain factory 转成同连接同步 SQL 消费；未知入口/profile/step fail closed。旧 usage/terminal factory绑定旧 fixture path，绝不能 cast 复用。

`closeWritersV2(root)` / `inspectWritersV2(root)` 在 writer-control-v2.mjs 内实际调用 openWritersV2，与新 entry 使用**同一个 writers.sqlite**。固定 close 在 registry transaction 重验身份、读取 entry/operation/unacknowledged step inventory、open→closed+closed audit 同步 COMMIT，然后重新观察；返回 `close_commit: committed|not_committed|unknown`、observed mode/事实、未完步骤，所有 writer_quiescence/drain_ready/production_permitted 为 false。重复 closed 是 observed_closed/no-op，不冒称新 COMMIT，不清 unknown、不 reopen。读控制 inventory 不执行 drain/lease revoke，不宣称业务已静止；inspect 若需 SQLite hot journal 恢复不称零FS效应。

锁序是 registry → S0 ledger 身份重查（openLedger.inspect 的同步事务立即结束）→ business；初始无 stage。现 ledger.inspect 实际取 .immediate 写锁，故不能忽略其锁。不能持 S0事务再取 registry，不能在已有 business 写事务反向申请，不能任意调用 ledger/controller 至 registry 的 callback。reservation 事务先结束、registry 重新取写锁并重验 open/代际/reservation 后，固定 business 同步 COMMIT 处于同一 registry 锁窗口；business事务不跨 await。registry ACK在 business正常COMMIT后，ACK失败返回 committed+coordination_unknown，不称 rollback。锁释放窗口中 close 获胜时 reservation保留、business不执行；原 cap 消耗，不复用。两进程真实 SQLite锁竞争验收这条协议。

取消用原 AbortSignal 实时 identity，执行前/同步COMMIT前检查；await 外部模型/IO时不持 registry/business锁，返回后重新固定消费。取消/撤销/sticky failure 保留实际已开始模型调用及 partial/unknown成本；COMMIT确定成功后取消不能冲销。一个同步 COMMIT 返回正常是 committed；写前拒绝且确定无提交是not_committed；抛错/死亡无法证明是unknown。mkdir/文件创建/rename独立 FS事实，不进入SQLrollback。进程死亡后从steps/results真实行诊断；旧cap永久无效，fresh recovery不得清closed、复活epoch或改已提交失败为rollback。
