# Spec: 遗留原文归档读侧完整性

> 内部原型安全修复；不回填、不重写历史原件或报告。

## 目标与边界

历史迁移给 `ContentItem.reader_eligible` 默认值 `1`，但该值对迁移前行不能证明 `raw_ref` 可读取、原文版本正确。新报告不得利用这种假阳性发布引用；既有报告保持原样并明确提示已确认的归档文件缺口。图谱／线索／机会已有的严格 v1 证据门保持不变。

本轮不把现时网页、数据库 `body`、FTS 或派生 HTML 伪称为生成时的原文归档；不自动更新历史 `CitationCheck`、报告正文或生产 `reader_eligible`。归档引用的逐字/语义质量问题另按原文核对，不能仅凭文件存在宣布通过。

## 验收标准

- [ ] AC1：新一轮校验前，内容必须有当前行绑定的、`committed` 的 v1 raw-archive effect；文件 hash、正文输入及 `content_hash` 与当前行一致。空 `raw_ref`、悬空文件、旧版 plain archive、effect 错配、归档正文与数据库正文不符均不得进入 LLM 一致性校验，相关引用 fail-closed。
- [ ] AC2：数据库 `body` 包含 quote 不是 AC1 的替代品。反例：来源正文含关键限定语，数据库正文/引文删去限定语；即使二者互相匹配，也不能作为已核验原文发布。通过的 v1 正例不得被误拦。
- [ ] AC3：报告定稿前、发布事务内及中断后的两条恢复发布路径，均按报告实际展示的引用绑定重新核对 `pass/support` 与当前 v1 原文；归档丢失、当前正文不再包含引文或当前归档绑定失效时不得发布新报告。绑定随发布意图持久化；旧的非空意图若没有绑定，不得直接恢复为 `done`。未展示的次要校验引用不能单独阻断报告。这个检查不等于“验证期原文版本”持久化绑定；若同一引文在更新后的正文中仍存在但上下文语义改变，当前版本仍需另外的不可变 source-version 设计才能完全识别，不能宣称已覆盖该竞态。
- [ ] AC4：既有报告正文、引用、历史校验记录和去重基线保持原样。关联的 `pass/support` 引用若当前原文文件缺失、空引用或不安全路径，页面显示准确的“历史归档当前不可用”提示；现时来源链接不能标为历史原件。无缺口时不显示该提示。
- [ ] AC5：读侧检查不改生产数据，不读取越界路径或跟随归档符号链接；只输出有界计数。任何生产迁移或历史修订须另行预览、备份、获授权后执行。
- [ ] AC6：受影响测试、`typecheck`、构建及与校验语义相匹配的真实模型安全评测通过。A1 不执行报告读侧路径，不能拿 A1 单独证明 AC3–AC4。

只读生产影响预览见 `docs/verify/c1-reader-eligibility-impact-2026-10-01.md`。
