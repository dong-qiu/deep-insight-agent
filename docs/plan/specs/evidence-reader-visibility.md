# B4：读者侧证据可见性

> 设计与验收契约 · 2026-09-28。对应技术债计划 TD-02 / B4；实现和静态快照影响证据见
> [B4 读者侧证据可见性核验](../../verify/b4-evidence-reader-visibility-2026-09-28.md)。

## 目标和边界

图谱节点、边和下钻卡片，以及技术线索、机会所附证据，都是**当前读者面**，不能仅因为过去的
`citation_check=pass/support` 就继续展示失效的来源。B4 只收紧读取，不修改 Analyzer、Validator、
Coverage、报告生成、历史报告正文或任何已落库判定；不得把原文存在性检查当成语义一致性检查。

历史已发布报告与管理员质量复盘是另一种**历史记录面**。它们保留发布时的报告文件、引用摘录和
不可变的脱敏 `content-v4` 元数据；当前 `ContentItem` 更新不得把新正文冒充为历史输入。

## 当前证据的准入

图谱与线索统一通过以下条件，缺一即不展示该洞察/证据，也不计入图的节点、边和数量：

1. 沿用现有 v6 证据门：batch 已完成并已审计、`source_quote_v1`、audit 是 `kept`/`kept_degraded`、
   audit 精确绑定当前 statement 与唯一引用、展示元数据安全，绑定引用有同 batch 的
   `reachability=pass`、`consistency=support`、`verdict=pass`。不能用另一个引用的 pass 顶替。
2. 绑定的 `content_item` 和来源存在，`reader_eligible=1`。当前正文必须可读，绑定 quote 按
   Validator 的同一 `compareKey` 规范化口径仍可定位；不得用仅存储于 citation 的 quote 代替正文。
3. 当前 `raw_ref` 必须**精确**绑定该内容的一项 committed raw-archive effect：目标路径、内容 ID、
   envelope SHA-256、大小和幂等键均与该 effect 的唯一 manifest 一致。只判断当前绑定；过去的
   unknown effect 不否决后来已提交的新版本。文件在读取时须可用且大小、SHA-256 匹配；缺失、
   权限错误、损坏、manifest 错位均 fail-closed。没有精确 effect 关联的旧内容即使
   `reader_eligible=1` 也不可见；不得自动改用 URL 重新抓取。
4. 对 `content-raw-archive-v1` 队列，文件哈希只证明 envelope 字节完整，还须校验其结构、
   `structured_body_sha256` 和当前 `content_hash`；用现有归一化/截断规则由 envelope 的
   `source_body` 重建正文，并要求与当前 `body` 相符，且 `contentHash(body)=content_hash`。
   数据库正文被单独改写、或 `body`/hash/归档任一方漂移，都不能借旧 pass 校验继续展示。

历史上已有**受控 effect 但归档仍是纯原文**的队列：它能证明归档字节未变，却缺少 envelope 的
结构化正文哈希，不能按 v1 的三方绑定规则自动升级。它与“没有可验证 effect 关联”的更早
队列分别统计、分别标识，默认不进入当前图谱/线索。若要保留这些旧资料，需先做隔离修复、
重采或建立等价的版本绑定规则并记录独立验收；B4 不静默回填。

同一次查询中，图装配、节点/边下钻、线索列表/详情/规划和机会附证据应复用同一可见性判定。
线索与机会列表的数量上限作用于通过该判定后的**可见结果**，不能先按原始评分截断、再过滤证据，导致较低排名的合格项被无证据候选挤掉；主题和通道筛选不得改变同一项的证据准入结论。
实施前先在**隔离静态备份（只输出脱敏聚合）**上按“无 effect / 旧纯原文 effect / v1 envelope / 缺失或损坏”
分队列统计：会退出当前图的洞察/节点/边、线索及机会证据数量，
以及每次图请求候选内容数、唯一归档数、总待读字节与现有 P50/P95。这个结果决定是否需先做
可审计的候选/时间窗上限；不能未经测量直接在默认“全部历史”图页增加无界文件扫描。
实现应批量查 effect，按同一请求的内容 ID 去重并共享归档核验结果；不得跨请求长期缓存正面
结果，以免文件消失后仍对外可见。以相同快照比较改前/改后的图页、下钻、线索与机会读取耗时、
读取字节和输出集合，明确性能预算与回退阈值后才准入代码。D3 的进一步优化不替代 B4 的可用性门。

## 历史快照例外

已发布报告的既存 Markdown 与引用摘录可以继续作为“当时发布的记录”读取；不宣称报告文件或
可变的 `citation.quote` 本身具备独立的不可篡改保证。管理员质量复盘在
`report_review_snapshot=published/complete` 且每次读取均重新核对 `content-v4` revision、
`snapshot_hash` 和 snapshot 白名单时，可以展示**历史输入元数据与内容哈希**。这只是历史记录
可见，不是当前原文仍可读的证明：页面
不得用当前 `content_item.body` / `raw_ref` 回填旧正文，也不得把该记录重新注入图谱或技术线索。
若历史原文确需打开，必须另有按 revision 锁定、授权可读且字节哈希匹配的不可变归档；现有
`provenance_revision` 不包含该能力，单独的旧 `citation.quote` 或一个 `content_hash` 都不足以构成
“历史原文可用”。没有该归档时明确标记“历史原文未保留/不可核验”，但不篡改或删除已发布报告。
legacy/partial 复盘不得升级为 complete。

## 验收反例

| 情况 | 当前图谱/线索 | 历史报告/复盘 |
|---|---|---|
| 当前 content 行不存在，citation 仍留存 | 不可见 | 已提交报告照常读；复盘只按冻结的历史元数据展示 |
| `reader_eligible=0`、归档正在替换/状态 unknown | 不可见 | 不回指新正文；已发布记录不被改写 |
| `reader_eligible=1` 但无精确 effect，或归档文件缺失、不可读、哈希不符 | 不可见 | 标记历史原文不可核验，不宣称当前来源可用 |
| 归档 effect 已 committed，但文件是早期纯原文而非 v1 envelope | 默认不可见，单列影响量 | 已发布记录仍可读，不伪称 v1 三方绑定 |
| 当前正文已替换，旧 quote 不再可达 | 不可见，即使旧 check 仍 pass | 旧 quote 仅作为当时发布的记录 |
| 当前正文被改写但仍含 quote，正文 hash 或归档 envelope 不符 | 不可见 | 不从当前正文回填历史 |
| 当前正文仍含 quote，但归档或 audit/binding 不合格 | 不可见 | 不将旧元数据升级为当前证据 |
| 当前归档/正文均可读且 v6 语义门通过 | 图、下钻、线索与机会证据一致可见 | 不改变已发布记录 |
| 高分但证据不合格的候选占满原始查询上限 | 继续查找后续合格项，直到可见项达到上限或候选耗尽 | 不影响历史报告 |
| 有完整、读取时哈希可核的 `content-v4` 历史元数据，但无旧原文字节 | 不作为当前证据 | 复盘可显示历史元数据和 quote，并明确原文缺口 |
| `content-v4` snapshot 或 `snapshot_hash` 被篡改 | 不提供历史旁路 | 复盘拒绝该输入元数据，不以当前行替补 |

实现次序：先以隔离 DB 和临时归档建立上述反例（应先复现当前失败），再收敛共享读取门；
运行受影响 DB/API/页面测试、typecheck、构建与脱敏快照读取性能对照。若需改动引用语义门或模型输入，
须停止纯读取切片并按 Eval-Gate 单独评估。独立评审核对最终 diff 与历史例外。
