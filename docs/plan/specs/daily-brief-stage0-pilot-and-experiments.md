> 2026-10-07 · 本页固定首个主题、读者目标和工程准备验收，不冻结缺少实测依据的 T04 数值，不开启生产。执行记录见[集成交接](../../verify/daily-brief-stage0-integration-handoff-2026-10-07.md)。

## 读者与重要性标注

首个试点主题是软件工程。目标读者为技术负责人和资深开发者，决策场景为工具链采用、开发流程改进及有条件的验证试验。消息应使读者理解技术变化、支持结论的依据、适用条件与限制，以及来源明确提出的影响。产业与安全随后分别使用产品/战略、防护/评估场景，不能自动套用本主题的重要性标签。

完整输入的重要性先于模型成品标注。保留未提取、未刊、单事实及负例输入。人工逐项决定真实事件、必须保留的维度、次要补充、必要限定与固定理解题；沿用既有确认，新增或争议项才请人裁决。来源无法证明的内容保留为缺口，不生成“无重要信息”标签。AI 可准备候选工作表，不能代替人工金标或阅读效果。

## 阶段 0 的工程验收

1. 重新核对 main、开放 PR、worktree 与工作区；创建独立环境，保护已有配置/私有材料，并明确每人文件所有权。
2. 准备全量输入 occurrence、全部定时尝试与失败、既有确认来源及待人工项；188 已见版本及其关联家族保留探索侧，未知家族隔离。
3. 交付可执行的协议预检/冻结工具。缺少人工完整性、来源家族、数字依据、资源身份或未见前瞻声明时必须拒绝冻结；不能输出成功冻结或开跑正式留出。
4. 细化共同版本化来源、命题、证据、验证与发布接口，标明已实现和缺失能力。共享代码修改由集成负责人另排顺序。
5. F 工具分别输出可观察钟、unknown 及原因；单主题/逐期/来源形态/首报与续报均能分层。无首报身份或读者遥测不推断实测首报/阅读年龄。
6. 每个切片由非作者 Agent 在新审查上下文复核；受影响测试、typecheck 通过，PR 按 `pre-pr-ai-review` 和 `eval-gate` 路由附证据，精确 head CI 通过后才合入。

完成上述工程准备可以交付阶段 0 工具和契约，但**不等于**完整 T03 金标或 T04 正式协议完成。T04 另须补齐有探索依据的样本/收益/绝对覆盖/非劣/阅读/token/成本/运行时间数值及资源指纹，在看正式留出结果前封存。正式窗口的起点必须晚于冻结；不因时间流逝自动开启。

## 执行依赖与发布门

第一波由数据、证据契约、F 基线三个独立 Agent 并行；集成负责人统一 v0 接口。第二波在公共接口核对后准备 C1、P、C、I 的离线输入和专用评测，每波最多三位实现/研究 Agent。正式 C1 离线对照还必须满足自身预检；同事件阅读卡正式评测与实现必须在 C1 增量和独立证据门通过后启动。

F/P/C/I 各自失败保持关闭，其他独立切片可继续。生产顺序为各切片专用门 → 单主题 shadow → 单主题灰度 → 按各主题证据推广；不得把一个主题成功外推到三主题。生产部署/开关启用另交具体不可变版本、核验与回退方案，并经用户确认。旧报告不重算，历史 artifact 不改写。
