# C1 / TD-09：备份与隔离恢复完整性

## 背景与边界

2026-09-29 生产只读盘点发现：每日 SQLite + reports 备份及 S3 同步在运行，但
`BACKUP_INCLUDE_RAW` 未设置，备份没有 `raw/`。因此现有备份只能称为部分备份，
不能作为“报告引用可回溯到原文”的完整恢复证据。本切片不修改历史报告、原文或
生产 live SQLite；不能用重新抓取替代原字节恢复。

## 验收标准

1. 新备份默认纳入 `raw/`；显式关闭时仍可保留 DB + reports 的部分备份，
   但清单与检查结果必须标记为不完整，不能返回“可完整恢复”，即使 DB 当时没有原文引用。
2. 每份新备份有版本化清单，列出 DB、报告正文和原文文件的相对路径、大小与
   SHA-256；清单不包含正文、密钥或生产绝对路径。备份后、隔离复制后均可只读校验。
3. 检查以备份 SQLite 中的 `content_item.raw_ref`、已验证 speaker map / transcript
   证据、已发布 `report.body_path` 和待删除生命周期保留的报告正文为准，
   对每个可映射引用核对备份中的文件；旧路径、空引用、路径穿越、缺文件、损坏文件
   必须显式计数并使“完整恢复”失败。旧备份无清单也不得伪装为通过。
4. SQLite 使用 `quick_check` 核验；清单和检查脚本不得连接或修改 live SQLite。
5. 用隔离测试目录创建备份、复制为恢复副本并核对哈希与 DB 引用；覆盖原文缺失、
   报告缺失、显式不备 raw、哈希篡改、危险路径和旧备份等反例。
6. 生产启用前先确认磁盘与 S3 空间、保留策略和当前历史缺口；上线后只能用新备份
   及隔离副本验收。生产恢复仍必须按 `operations.md` 先回放脱敏登记册，不运行
   `ops/db-restore.mjs`，不重写生产文件。
7. 新备份不完整时，轮转不得删掉滚动窗口外最后一个有完整清单的恢复点；
   本地最多额外保留这一份，且任何新格式恢复点最长 90 天，避免超过 100 天
   脱敏登记册窗口。旧格式和人工命名备份不自动删除，需另行逐项盘点。
8. 异地同步只上传 90 天内的新格式清单目录，核对文件清单、哈希并拒绝链接和
   额外文件；旧格式本地备份不得被每日同步重新上传。生产 host cron 的迁移
   与首份新备份核验分开验收，迁移前不宣称 C1 异地恢复完成。
9. 在线 SQLite 备份不得把 WAL 模式的离线副本直接封存：清单前须切为单文件
   DELETE 模式，且不得产生 `insight.db-wal` / `insight.db-shm`。校验器遇到
   未规范化 WAL 快照必须在打开 SQLite 前拒绝，不能以只读核验制造旁文件。

## 已知历史例外

报告的 292 条正文路径中 14 条在 live 和备份均缺失（生成于 5–6 月）。
708 个已发布报告实际引用的内容中，653 个原文在 live 可读，55 个为空、旧路径
或已缺失；旧缺口不能靠开启备份开关修复。新备份仍须如实标为部分可恢复，
直到另行核对这些历史引用的处置。

此备份不得作为恢复点，保留供后续盘点；本修复不删除或改写它。
