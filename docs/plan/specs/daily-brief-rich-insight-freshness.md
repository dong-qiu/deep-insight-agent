# Daily Brief：多句洞察、原文深读与时效性优化方案

> 2026-10-05 · 产品方向与分阶段方案已获用户确认；各工作流仍须分别通过评测、实现评审和生产准入。适用于**新生成**的 Daily Brief；旧报告不回填。
> 依据：[使用反馈诊断](../../verify/daily-brief-product-feedback-diagnosis-2026-10-05.md)、[三方独立评审与共识](../../verify/daily-brief-rich-insight-plan-review-2026-10-05.md)、[信息完整性计划](daily-brief-information-density.md)、[原子事实与证据图](atomic-insight-evidence-graph.md)、[播客转写规格](podcast-transcript-acquisition.md)。

## 目标与边界

读者应在一条消息中理解**发生了什么、主要观点为何成立、适用于哪里、对我们的工作有何启示**；有可行动的技术对象时，能继续追踪为技术线索。多句是表达方式，不是最低字数。原文只含一个重要事实时保留短讯；没有原文支撑时不得补写背景、机制或观点。

保持两层单位：分析和校验仍以独立事实/观点命题为单位，每项绑定具体原文和必要限定；日报以同一真实事件或同一研究工作的**阅读卡**为单位，将已核验命题组织成数句。每个来源断言都保留自己的证据绑定；后续若允许编辑推论，须作为独立类型绑定已验证前提，不把前提的引用说成原文直接支持推论。不能把一条引用重复用于支撑整段，也不能把同一篇文章拆出的多条引用称为多源印证。

本方案的产品方向已按 [ADR-0043](../../develop/decisions.md#adr-0043-daily-brief-分离来源观点与有界工作启示)确认；这**不批准**模型自由推论进入现行报告。`对我们的启示`的独立分析判断须另有类型、评测和发布门；此前只能呈现原文作者明确提出且通过验证的影响，并注明归属。

## 读者侧内容契约

| 模块 | 读者应看到什么 | 缺少证据时 |
| --- | --- | --- |
| 核心变化/主张 | 事件变化或论文/嘉宾的主要观点，附来源和时间 | 不能出刊该主张 |
| 依据与机制 | 关键机制、比较基线、数据或嘉宾给出的理由；明确“作者报告/嘉宾认为” | 不推测，必要时只刊短讯 |
| 范围与局限 | 样本、版本、实验环境、发布阶段、反例或不确定性；必要限定贴近对应结论 | 不把局部结果写成普遍结论 |
| 对我们的启示 | 先展示来源明确表达的影响；后续可独立标注“编辑推论/待验证”，列出所依赖事实和条件 | 不伪装成来源观点，可省略 |
| 技术线索 | 具体模型、方法、工具、基准或风险控制，说明对应的证据与可验证问题 | 缺少具体对象或验证问题时不展示线索；不自动推荐采用或立项 |

阅读卡不强制填满五栏；通常用数句表达，复杂来源可更长，但以整刊阅读预算和理解题检验是否冗长。主结论、关键依据与必要限定必须在正文可见，不能藏在展开区；短讯也可只有一两句。每个事实片段能点开原文位置、内容版本和校验记录。现有 `TechLead` V1 只从 `pass` 事实确定性派生，尚不支持自由生成“为什么值得验证”；先展示有事实支撑的具体对象，后续在 `TechnologyOpportunity` 规划层另立候选对象，分存已验证事实 ID、工作假设及验证动作并单独评测。未通过现有 `pass` 白名单的事实不能进入线索。

### 四种信息状态

1. **原文直接支持**：事实、论文作者结论、嘉宾本人观点，分别标出发言主体、证据位置与语气。
2. **来源明确给出的解释**：例如作者说明机制、报告给出原因；仍按来源观点核验，不改写成系统已独立证明。
3. **我们的有界启示**：仅在新契约、专用评测和发布门批准后上线；作为独立的 typed analysis claim，绑定所有已验证前提、适用条件、可能失效处和验证动作。审核者与发布判据、artifact/索引/通知/导出的同一投影以及关闭开关的回退都须定义，不混入事实正文。
4. **材料不足/未知**：如只有摘要、节目简介、无可靠说话人映射、论证不完整；降级展示，不声称已读全文或已提取嘉宾观点。

## 按来源形态提取

### 论文：从摘要发现，到原文核验

当前 arXiv 适配器只保存 API `summary`。新增全文采集只放在 `src/lib/sources/`：以论文标识和**对应版本**关联现有摘要与新取得的官方可用 HTML/PDF，但全文必须写为独立的不可变证据版本或新的 `ContentItem`，不得原地替换摘要正文或迁移旧引用。保存原始文件、解析正文 hash、版本号、抓取时间、章节/页码/段落定位及解析状态；引文 locator 必须映射到归档版本内的连续正文 span，并通过原文/正文/引用三方核验。遵守现有访问与归档规则。优先复用成熟的文档解析器，先在冻结样本上比较 HTML、PDF 解析质量与成本，不另造 PDF 解析器。正文超预算时按问题、方法、实验、结果、限制做有覆盖记录的分段提取；不再把正文前 1 万字当成已读全文。表格、公式或图像无法可靠抽取时标为缺口，不从摘要补出正文结论，也不能用摘要引用证明全文才有的结果。

结构化提取 `研究问题 → 方法/对照 → 核心结论 → 证据（数据、基准、样本） → 适用范围/局限 → 来源所述影响 → 技术线索候选`。区分作者声称、实验实际观察、系统的启示；每个结论都检查比较对象、统计口径和限定。全稿获取失败可继续刊摘要级短讯，但标记“仅据摘要”，不生成“论文证明了为何如此”的深读卡。版本更新应比较新旧事实，只有实质新增才续报。

### 播客：从节目简介，进入可归属的发言

复用现有 `podcast-transcript-acquisition` 的 `off → observe → enabled` 路线和 shadow 证据包。首版只取发布者提供的公开 transcript；独立 ASR 不在现行播客规格的首版范围内，若需要须另立决策和评测。保存节目/转写版本、时间戳/段落、说话人映射及不确定性。现有规格规定 `enabled` 仅为**新 URL**写生产 transcript、旧 show notes 不原地升级；若要在同一旧节目后来补转写，必须先定义与原节目关联的新增证据版本、既有引用保持不变的规则及命题级续报资格，不能假定打开开关即可实现。长转写先定位主题相关段，再在上下文窗口中还原观点、理由、例子、反方和限定；提取多处相关发言时不得跨段拼接成伪引语。

核心输出是“**哪位嘉宾提出什么观点，基于什么经历/证据，适用条件是什么**”，而不只是节目介绍。访谈者的问题、主持人的概括和嘉宾回答分开；没有可靠 speaker map 时只可写“节目转写提到”，不得归到某位嘉宾。RSS 只有 show notes 或转写失败时，可刊已核验节目简介事实，但不称为嘉宾核心观点。`enabled` 前须先通过既有说话人 fail-closed、来源配对、引用校验和独立留出门。

### 网页、新闻与技术博客

短公告保持精练。长文要跨导语、正文关键段、结果和限制提取，记录覆盖到哪些章节；公告与媒体转述、已发生与计划中、实测与营销主张分开。先试已有全文抓取和分段能力，再比较额外模型提取与规则/开源工具在同一冻结来源上的**可刊增量**，不要以原始候选数评定效果。

## 时效与数量：单独优化，不靠放宽证据门

建立 `事件发生/论文版本/节目录制与发布 → 来源可获取/发布 → 首次采集 → 入选 → 提取完成 → 证据通过 → 出刊` 的分段时钟；分别标出能核验和未知的日期，同 URL 更新不能用最后 `fetched_at` 假装首次发现，也不能把旧事件的新转载算成新事件。读者打开时间仅在已有合法、可靠的遥测时另列，不作为首发依赖；没有遥测时可用固定阅读时点作**情景估算**，不得称为实测。按主题、每期、来源形态和首报/深读续报分别测出刊年龄的 P50/P90、24/48 小时比例，以及来源可获取后的处理延迟与阶段损失；原始发布日期和版本更新时间两套钟均保留。当前探索样本在出刊时 73 条中有 16 条已达 48 小时；它不是逐份认证的生产基线，也不能解释全部延迟来源。

时效优化独立于同池多事实编排。先在**固定完整来源池**上、相同分析 token/成本预算下，离线比较近期事件优先排序、每主题 15 个分析名额的分配、来源覆盖、采集频率和刊期；新入选内容必须重跑提取、展示审计、validator 与历史门，不能拿同一合格候选池的 B1 结果声称改善采集或入选。若延迟主要在采集，调整来源轮询与抓取失败重试；若在入选，调整近期/重要事件名额；若在证据门，改进逐项提取和可定位引用；若在每日一次的出刊等待，比较较晚截点或有新事实的补充刊，分别核算成本与读者时效。保持关键词/重要性、验证白名单和实质新颖性门。发布选择从“URL 或改写后的句子是否新”升级为“**真实事件及其重要命题是否已刊**”：旧命题不重复，旧事件有新结果可以注明续报。每期同时报告**独立重要事件数、关键维度覆盖、48 小时内有证据消息占比、重报率和空刊率**；不得以拼短讯凑条数，也不得仅为新鲜度丢掉重要事件。

为避免“全文深读使消息更旧”，采用两种交付时机：近期事件具备足够证据时先以简明消息刊出；论文全文或播客转写稍后可用时，以**已刊 artifact 的命题集合**而非新 URL/抓取时间判断增量。此前未刊、可定位且独立通过审计和 validator 的重要方法、论据、反例、适用条件、局限或嘉宾观点，如会改变对结论的理解，可标为同事件“深读更新”，链接前刊；旧结论只作简短、有绑定的前情，不计为新事实、独立事件或近期首报。仅换说法或拉长解释则不进入新刊，可在既有卡片的版本化阅读页补充，不改写历史发布 artifact。只有新的“我们的启示”时，须待独立分析判断发布门通过后，才可在标明来源事实未变的“分析回访”中呈现；它不计事实增量或近期新闻，并须限制频次和阅读预算。命题级历史判别、来源版本和续报发布均是论文/播客深读生产启用的前置完成门，当前快路径不支持旧事件续报。

## 实施顺序与完成门

| 工作流 | 交付 | 完成标志与读者能得到什么 |
| --- | --- | --- |
| 0. 沿用 S0/T03/T04，冻结新口径 | 不重做已完成的 T01/T02；继续封存来源家族、事件/重要维度、阅读题和 B1 门；另以前瞻观察建立旧备份无法恢复的首次采集/处理时延基线。为产业、软件工程、安全分别写明目标读者与决策：产品/战略信号、工具链/开发流程、防护/评估；未定义受众的启示只作待验证假设 | 旧年龄仅作探索，缺失字段保持 `unknown`；新留出与旧探索材料隔离，预登记分母、样本数、失败处理和阅读预算 |
| 1. 多事实新刊首发 | 沿用 ADR-0036 的同池、同事件证据组，先试一个主题；并行做时效分段诊断，不把未上线的时效实验计入收益 | 读者得到更完整的事件事实、来源明确的解释和限定；固定合格候选池上重要维度与理解提升，关键事件召回、重报、时效不退化，错误归组/未支持断言为零；全展示面同一 artifact。此步**不宣称已提供我们的独立启示、论文全文或嘉宾深读** |
| F. 独立时效切片 | 针对已定位的最大延迟段，选择可上线的采集、入选、校验或刊期改动；在固定完整来源池、同成本预算下配对重跑生产链路 | 分主题、每期和来源形态的首报时效改善，重要新事件与维度召回非劣，重报/空刊不恶化；未达到门槛则保留旧策略，不用 B1 编排结果代证 |
| P. 论文全文深读 | 版本化全文采集、解析覆盖账本、分段提取、命题级续报及论文专用评测；先 shadow 再灰度 | 读者看到结论、依据、范围、局限；抽样追至归档全文版本及定位 span，已刊摘要引用不变。新事件深读可先试，旧事件深读更新须待续报门通过；误引或越界结论为零容忍 |
| C. 播客嘉宾观点 | 现有 shadow → 来源级 `enabled`，补说话人映射、观点—论据链、同集转写证据版本、命题级续报及专用评测 | 读者看到可归属的嘉宾核心观点与依据；不误认主持人/嘉宾，不拼接跨段引语。无 speaker map 则只给未归属转写信息；旧节目深读更新须待续报门通过 |
| I. 有界启示与线索 | 阶段 0 即并行离线标注来源影响与工作启示；上线前另定 typed analysis claim、审核与发布门、全展示面/回退规则。线索的分析理由留在规划层候选，不伪装成 V1 `TechLead` 事实 | 读者可区分来源观点与我们的判断，每条公开启示有已核验前提、目标场景、失效条件和验证动作；独立盲评通过前只刊来源明确的影响 |
| G. 三主题推广 | 上述工作流可并行准备、分别通过来源/推论门后按主题灰度，监控与阅读复测 | 连续前瞻窗口分别达成时效、重要事件/维度覆盖、准确性和阅读负担门；成本与运行时间受控，失败可回到旧路径 |

阶段 1 的编排若缺少合格互补事实，应先做独立的提取/展示审计实验，不因赶发布而放行未验证候选。P/C/I 的 shadow、标注与评测可和阶段 1 并行，但各自生产启用依赖来源身份、命题续报或推论专用门。每阶段修改 prompt、模型、来源、校验或评测集时运行 `eval-gate`，并对报告选择、历史去重、渲染与恢复跑生产路径回归；只读文档阶段不需要拿 A1 冒充产品验收。

## 建议冻结的验收指标

- **真实性硬门**：发布代码路径中 `blocked`/无验证引用为 0；分层人工抽检中未支持事实、错归属、必要限定缺失、错误事件合并均为 0。来源位置、版本及引用可回溯。论文 HTML/PDF、摘要回退、转写有/无可靠 speaker map、长短来源分别预登记样本量、失败项、误接受/误拒绝和成本门；“样本零错”不等于总体零风险。
- **信息量**：每条消息的已核验**重要维度**数、读者理解题正确率、读者对主要观点/依据/限制的复述；不以字数、句数或引用数代替。
- **覆盖和新颖性**：固定完整输入中的重要新事件召回、同事件关键维度召回、已刊命题重报率；分主题报告空刊与完成率。
- **时效**：首发 B1 要求不退化；独立 F 切片按主题、每期、来源形态和首报/续报报告来源可获取→出刊延迟、原始发布/版本更新→出刊年龄的 P50/P90、24/48 小时占比及超时原因。以前瞻基线预登记相对改善、绝对 P90/超龄期数上限，且关键事件召回不下降；没有打开遥测时不宣称改善实际阅读年龄。
- **深度与成本**：全文/转写成功覆盖率，重要观点及其依据/范围覆盖率，提取到可刊的转化率，单位可刊消息的抓取/模型成本和管线耗时；质量失败不由更长文本抵消。

旧的“每条 ≤120 字”、单事件代表项和中立无推断要求与目标展示有冲突。[报告规格](report-generation.md)和[产品定义](../../concept/product-definition.md)已标明本方向与现行契约的分界；每个上线切片仍须版本化细化自己的行为及 AC。在推论专用质量门完成前，新刊只能输出已核验的事实与来源明确观点，不能把“启示”当自由润色功能上线。
