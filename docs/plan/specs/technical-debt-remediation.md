## 目标与边界

在内部原型快速迭代的前提下，先修失败边界，再减少验证和运行成本，最后按需拆分模块。
本计划承接技术债审计的 20 项编号（TD-01 至 TD-20），不重新开启已取消的 P1 产品任务。

- 不改变模型、provider、thinking、prompt、引用白名单、语义一致性及展示覆盖规则。
- 不接触生产数据库，不复制 live SQLite，不因重构重写历史迁移或报告。
- 不引入微服务、替换 SQLite 或建立新的合规平台。
- 每个实施切片须有验收测试、独立审查和清晰回退边界；合入和部署分别核验。
- A 批已合入并完成生产核验；当前启动 B1a 登录限速，B1b 会话撤销另切片交付。
  后续切片逐项确认前置条件，不将“已有方案”写成“已经完成”。

## 第一批详细验收

### A1：一个测试清单，两个入口

1. Node 测试发现仅扫描仓库 `ops/` 下的 `*.node-test.mjs`，稳定排序、不跟随目录符号链接。
2. 包含 cleanup、forward observation、gen-env、Multica 及测试入口自身的回归测试。
3. 子进程失败、信号退出、启动失败及空测试清单不得返回成功。
4. `npm test` 与 `npm run test:coverage` 调用同一个入口，CI 无需另维护一份列表。
5. 双版本类型检查通过独立 `tsconfig.tools.json` 包含 ops 和 tests 的 TypeScript 文件；
   不扩展 Next 的应用构建根文件，保持 Docker 排除 evals/tests 的边界；不把 JS 文件误称为接受严格类型检查。

### A2：成功后发布连接

1. `getDb` 在 schema、deployment、报告/raw 协调、默认方向初始化全部成功之后才赋值单例。
2. 任一步抛错，关闭当前连接，保留原始错误；后续调用必须重新初始化。
3. `openDb` 自己的 pragma/schema/bootstrap 失败也关闭其拥有的连接。
4. 成功路径保持现有检查次序、迁移及协调行为；`closeDb` 仍可重复调用。
5. 真实内存 DB 覆盖连续检查失败；故障注入只补充无法廉价构造的协调失败，不替代真实路径。

### A3：只收敛已识别的危险数值

本批范围：`VALIDATOR_RETRIES`、`VALIDATOR_RETRY_BACKOFF_MS`、`VALIDATION_DEGRADED_ALERT_RATE`、
`LLM_TIMEOUT_MS`、`ANALYZE_BODY_CHARS`、`SELECT_WINDOW_CHARS`。

- 缺失使用原默认值；显式空值与非法值报配置错误，不静默换用另一个执行配置。
- retries / backoff 是非负安全整数，`0` 有效；timeout 是正整数且不超过 Node timer 的有符号 32 位上限。
- alert rate 在 `[0,1]`；正文/窗口长度是正安全整数。
- `chunkWindows` 的显式 size 参数也校验，包含空正文调用；不能仅校验环境变量。
- 合法输入的窗口边界、连续原文切片、截断结果不变。增加旧算法与当前算法的固定语料对照。
- getter 继续在调用时读环境；Analyzer 长度常量仍在模块加载时读取。不宣称全局启动预检已完成。
- 本批不改已有 `LLM_MAX_RETRIES` / transient retries 的回退或限幅策略，也不改变 thinking。

## 验证、审查与回退

- 先保留 DB 连续失败反例，再实现；窗口非法参数测试在保护加入后运行，避免测试进程死循环。
- 定向单元/集成 → 运维 Node 测试 → 双版本 typecheck → lint → coverage → production build。
- 按 eval-gate 核对 AI 面差异：本批只改变非法配置失败路径，不修改正常配置下的模型输入、
  prompt、数据集或判断规则；用确定性对照和现有 Analyzer/Validator 测试证明正常路径不变。
  如发现合法配置路径语义发生变化，暂停并补真实模型 scoped safety 证据，不以无关 A1 绿灯替代。
- 独立 review 核对最终 diff、反例和验证证据；高风险发现修复后复查。
- A 批无 schema 或历史数据变更，可通过回退代码回退；非法配置必须先纠正，不能靠回退恢复危险循环。
- 创建 PR、合入、生产发布分别记录状态；未经 CI 与部署核验不写“生产已修复”。
