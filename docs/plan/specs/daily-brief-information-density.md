# Daily Brief 信息完整性优化：实施计划

> 日期：2026-09-27 · 状态：独立评审达成共识，可进入 S0/S1 / 待实施。本文不代表功能已实现或生产准入已通过。
> 架构提案：[ADR-0036](../../develop/decisions.md#adr-0036-daily-brief-以事件组织已验证事实提案)。
> 评审发现、分歧及复核结论见 [独立评审记录](../../verify/daily-brief-information-density-plan-review-2026-09-27.md)。

## 1. 目标与依据

用户反馈：每条消息信息量不足，通常只有一句结论、一个引用，难以理解事件的具体变化和适用条件。
本次只读抽样发现，9 月 23–26 日的 11 份 Brief 共 64 条洞察、64 条展示引用；
这些洞察在 citation 表实际有 78 条引用。最新一轮展示审计共 125 条候选、34 条保留，
之后仍有新鲜度和历史去重过滤。数据为当时的生产抽样，不能归因成单一模型效果，也不是后续评测基线。
原文、报告明细、凭据和生产快照不进入版本库。

目标：读者以一条消息理解一个事件的主要变化、关键结果及必要条件；系统继续以单个事实执行验证。
一条事件消息可包含多个已验证事实，每个事实独立绑定来源，不把多个弱引用合起来证明一个新结论。

本计划承接 [原子洞察与证据关系图](atomic-insight-evidence-graph.md) 的报告编排方向，
不是重建一套平行事实系统。其不可变证据、artifact 绑定、发布事务和分层验证要求仍适用；
不能以“只是排版”为由跳过进入持久化报告编排所需的证据。该规格的阶段 P1/P2
与 [休眠的完整性/驾驶舱 P1](../p1-dormant-reentry.md) 是不同范围，本计划不启用后者。

### 成功表现

- 多事实事件被组织为一条消息，而不是若干缺少上下文的短条目。
- 原文有重要结果、范围或限制时，日报尽可能覆盖；必要限定与结果一起展示。
- 只有一个可靠事实的事件仍可作为简讯，不为字数或引用数量凑内容。
- 事实、引用、事件数分别计量；消息数量减少不被误记为事实产出下降。

### 范围

首版只改变新生成的 `brief`；`initial_digest`、`deep_dive` 和历史 artifact 保持原契约。
复用现有 Insight、Citation、展示审计和 validator，不先更换模型。
不加入自由综合润色、跨源共识推断、全网补搜、历史全文重写或完整图谱/API 迁移。
补充提取只使用本轮已选 ContentItem 的受控快照；不在页面或 agent 中另建抓取通道。

## 2. 拟定读者体验

一条消息默认展示主事实，随后并列 1–3 个互补事实，各句有对应引用编号。
证据区保留逐字 quote、来源、日期和可达锚点；移动端、导出和通知采用同一已发布投影。
明确标注来源篇数：三个事实、三个引用来自同一文章仍标为单源，不能呈现成三源印证。
第一版标题复用完整的已审计主事实，或采用“事件 1”等无事实含义的标签，不生成自由标题。
不依赖悬浮才能看到关键限制；正文先保持事实原句，标签仅作固定分类。

示意结构（不是可发布事实）：

```text
主事实 / 发生的变化。[1]
具体能力或量化结果。[2]
适用范围或独立的限制事实。[3]

[1] 原文证据、来源、日期
[2] 原文证据、来源、日期
[3] 原文证据、来源、日期
```

重点消息暂以 2–4 个互补事实、约 120–220 个中文字符作为离线试排范围，
不是生成最低字数或已生效门槛。字数包含读者结论、不包含原文证据；不得按字符截断完整事实。
当前 [report-generation](report-generation.md) 的“每条 ≤120 字”和事件上限应在 S0
根据阅读计时修订，试验前冻结全刊阅读预算，不能静默改写原规格。

## 3. 数据及语义契约

### 3.1 保留事实校验，新增报告编排投影

拟新增 `BriefStory`（名称可在 S0 定稿），它是报告内的展示组，不替代 Insight/event 的事实身份。
每组保存主事实、按序成员、归组依据及策略版本。每个成员仍指向自己的 Insight 和唯一主 Citation，
并绑定其发布时的证据材料。不得把其他成员的 citations 拼入代表 Insight。

已知缺口：当前 `content-v4` revision 保存的是来源元数据、content hash 和 body_length，
没有原文/quote/span；analysis revision 以计数为主，validation revision 只保留部分检查摘要。
revision 存在不等于已有完整事实快照。S0 必须列出字段级复用/缺口表，S2 补齐最小不可变成员证据包：
最终事实文本、唯一主引用、逐字 quote 与 locator/有界 span、源内容版本和受控归档绑定、完整展示审计、
validator 检查与策略版本。已有 content-addressed 受控材料可以按 hash 引用，但发布及恢复必须验证
其可用性和绑定，不只存指向可变行的外键。无需新存全站全文或建立全局事实图。

拟定投影内容：

| 对象 | 最低字段/不变量 |
|---|---|
| Story | report/artifact/version、report-local story ID、主事实 ID、有序成员 ID、归组审计/策略版本 |
| 成员绑定 | Insight occurrence、不可变成员证据包 ID/hash、citation ref、来源 content hash/revision、完整审计/check 绑定、最终文本 hash、展示锚点 |
| 发布清单 | 有序 Story/成员/引用、renderer/selection/grouping 版本、artifact hash；与正文共同固化 |
| 计数 | story_count、published_fact_count、published_citation_count、来源 item/site 数，不能互相替代 |

`reader_statement` 继续要求通过审计的精确哈希绑定；缺失时沿用 quote-only 回退。
任何结果成立所必需的主体、比较基线、范围、条件、极性和模态，必须在该成员自身完整保留，
不能把必要限定拆到可删掉的另一成员中。报告层只并列原句，不添加“因此、共同证明、领先”等关系。

具体 schema、外键、索引及迁移在 S2 固化于 `schema.ts` 和 `architecture.md`。
先完成上述实际缺口映射；不凭当前可变 Citation/Insight/check 行重建历史发布依据。
该切片不宣称完成原子证据图规格中的全部 P2。

发布延续既有 intent → staging → commit 协议，不假定数据库和文件系统可用一个事务原子提交。
`saveReport` 正常提交与 reconciliation 恢复提交必须共用版本化发布 guard，核对正文 hash、
成员/引用/审计的完整集合、顺序及版本；不能只在 pipeline callback 中添加检查。
同 report ID/effect 的恢复保持幂等。新的显式重跑仍是新的报告尝试，不能声称跨尝试/跨通知渠道 exactly-once；
提交后的通知与材料核验不混为一谈，未知投递结果不由本功能自动重发，不为此新增全量 outbox。

S2 须附新增资源处置矩阵，逐项列 Story/成员包/manifest/预览/索引/PPT/影子文件的所有者、
读取权限、撤下或销毁策略、可保留的非内容 hash，以及 tombstone/replay 接线与顺序。
报告级撤回覆盖全部派生材料；来源级删除先定位受影响报告，按既有删除政策处理，不能动态删成员改写
已发布 artifact。若现有政策不能覆盖，先收口该切片的处置规则再启用；恢复先回放 registry，后开放读取。
不可变材料不意味着永久可读，不得借审计入口绕过 redaction。

### 3.2 事件归组

- 第一轮离线试排使用人工确认的归组，单独测编排是否改善阅读；不能据此宣称自动归组可用。
- 自动路径先限定同一 topic、同一 ContentItem 版本内的同一事件；跨文章/跨来源归组留后续。
- 同文章、同域名、同实体、同 event_id 均不是充分条件；聚合文章中的多个事件必须分开。
- 候选归组必须有同主体、同版本/时间脉络和同一行动/结果的依据，并保留来源定位；
  模型提出候选不等于批准。S0 对严格规则与有界语义复核作离线比较，选定可复验策略后冻结。
- 不确定、互相冲突或归组检查不可用时，回退独立简讯，不把整个 topic 变成失败。
- 组内不同事实并列展示；数值冲突不得自动取平均、选多数或改写成共识。

### 3.3 选择、新鲜度和去重

目标顺序：事实审计白名单 → 标记精确重复事实及事件候选组 → 新鲜度/历史事实选择 →
选择重复事实代表及最终分组 → 事件排序及事实预算 → 发布绑定与渲染。
候选标记阶段保留全部 occurrence，不提前丢掉可能是唯一近期/新增证据的较低排名项；
选择和渲染必须消费同一份确定结果。

1. 修改当前“同 event_id 只留一个代表项”的规则：同事件不同事实可以成为组内成员；
   相同事实仍只选一个代表，各原始 occurrence 保留。不能先执行旧事件折叠再尝试组装。
2. 组不能携带被挡住的事实：每个成员都必须通过自己的审计、pass/support 和新鲜度规则。
   首版不借一个新成员带入已发布或不满足新鲜度的旧背景；背景回填另行设计。
3. 日报更新仍要求实质新事实。单纯换 quote、改措辞、更新 URL 或来源抓取版本，不构成新事件。
4. 当前历史判定用 content_item_id 识别新增证据，会拦住同文中的新事实。S0 分开定义三层身份：
   命题身份（发生了什么）、证据 occurrence（哪个来源版本/quote 支持）、报告成员绑定（在哪次发布使用）。
   来源 revision 包含抓取时间，quote/span 也可能变化，二者不能进入证明“命题新增”的混合指纹。
   严格命题指纹只能确定重复，疑似同义改写的新颖性须有界复核；模型自报新 ID 不是放行依据。
5. 同一历史窗口按 occurrence 分流：新版用命题发布记录判断；legacy 继续原保守路径。
   新版缺命题身份不得按未发布放行，legacy event 也不能无差别覆盖已具备独立历史判定的新版事实。
   两类历史证据取并集：任一确认已发布即不重报；仅 legacy 匹配、无法确认新命题时保守排除并记录原因。
   S0 给出决策表，覆盖同文新事实、同义改写、仅重抓/换 quote、同主体不同版本及 off→on→off。
6. 非近期、未发布事件仍受最多两条“补充发现”限制，按 story 计数并明确标注；
   全刊事实预算另计，防止一个组绕过规模限制。
7. 被排除的成员分别记录重复、新鲜度、预算、分组等原因，不能笼统归为“模型拒绝”。

### 3.4 有界补充提取

根据事实供给诊断决定离线实验顺序；编排素材不足时，S1 可并行验证提取可行性，
不要求编排先上线。线上补提取仍须独立通过增量收益、安全和资源门。目标是互补内容，不是让原句变长。
按产品发布/研究/安全/行业动态记录适用的信息维度，缺失或不适用均可明确返回。

- 分别试验首次 analyzer 的互补提取策略与可选额外一调，不能把首次 prompt 改动混入“只编排”对照。
- S4 由 scheduler 显式向 runAnalysis 传递报告类型和提取策略；`initial_digest`/`deep_dive`
  与 brief 基线保持原路径。互补首次提取和额外补提取都必须有明确模式与开关，关闭后恢复基线提取，
  不能只关闭第二次调用却继续使用已改写的首次 prompt。
- 有界补充输入只包含选定原文快照、已验证事实及缺失维度；外部正文继续作为不可信内容处理。
- S0/S4 开始前冻结每 topic 可补事件数、每事件调用数、额外 token/时间预算；
  默认关闭，单事件至多一次补充请求，不设置“直到补满”的循环。
- 新事实重新走展示覆盖、独立复核及 validator，不直接展示次级 citation.claim 或审计拒绝记录。
- 没有证据、预算耗尽或补充调用失败时保留原先已通过的简讯；必需的原始审计失败不得因此被吞掉。
- 首次分析及补提取缓存/审计均包含实际 report type、extraction policy 指纹和 model/prompt/output 版本；
  补提取另含 source hash、topic、目标维度、已有事实集合 hash。旧/新、冷/热缓存不得跨策略命中。
  有限预算和取消传递须覆盖所有子调用，保留 usage；遵守现有 provider 完成终态不得自动付费重试的规则。

## 4. 分阶段交付与依赖

主交付顺序：S0 → S1 → S2 → S3；S4 的离线可行性支线可在 S1 开展，
生产接线依赖 S2/S3 的证据绑定和展示能力，是否启用按自身增量门决定。S5 只负责观察与扩大。
每个实现 PR 独立提供相应证据，不把后续全部工作塞入一个大 PR。

| 阶段 / PR | 具体任务与主要落点 | 交付物与完成条件 |
|---|---|---|
| S0 / PR-1：冻结实验协议 | 对齐旧规格；盘点源文→提取→审计→选择→展示的损失，定义三层身份/证据包缺口，标注固定事件全集 | 探索集初测后冻结 manifest、分层、阈值、阅读/调用预算；此时接受实验边界，不提前声称策略获益 |
| S1 / PR-2：离线消融验证 | `evals/` 对比 A/B0/B1，人工归组与自动策略分别评分；必要时增加首次提取/额外一调的独立可行性支线 | 留出盲评及全刊非劣；区分编排、选择、提取收益；结果决定进入哪个切片或修订/停止；S2 前固化已验证的策略与 ADR |
| S2 / PR-3：绑定及选择 | `types.ts`、schema/迁移、report-gen、pipeline、report-review/reports 共用 guard；身份历史、资源处置矩阵、off/shadow 配置及隔离 | 新旧兼容；正常/恢复提交、重试和删除重放测试；关闭时选择等价；影子不污染发布历史或通知；需要语义调用时同时过语义门 |
| S3 / PR-4：全展示面交付 | 确定性编排；Markdown/HTML、页面/预览、卡片、索引、通知/PPT；按 topic 启用开关和最小停用手册 | 全展示面消费固化投影；首次 on 前明确最低兼容镜像并完成 on→off→on 回归；正常新报告人工验收 |
| S4 / PR-5：有界提取 | analyzer、scheduler/pipeline 类型与策略传递、独立模式、缓存/审计、定向 eval；固定 provider/model | 相对实际编排基线有新增正确重要信息；非 Brief 与 off/on/off、冷/热缓存隔离；真实安全收据；调用/预算/取消降级可复现 |
| S5 / PR-6：观察与推广 | 聚合诊断、操作手册完善与验收记录；模型 A/B 后续独立实验 | 达到预登记稳定运行和人工验收后扩大主题；开关/兼容/回退能力不得延至此阶段才交付 |

S2 的持久化关系设计必须满足原子证据图中本切片涉及的 artifact/FactBinding/证据快照/事务
前置条件并记录映射，未满足时停留离线/影子。不得顺带启用 dormant P1 基础设施或外部接口。

## 5. 离线比较与发布门

### 样本与分组

建议初始试验覆盖三个日报主题，各至少 10 个事件，总计至少 30 个事件；
区分多事实可补齐、真正单事实、聚合文章多事件、同主体不同版本、带必要限定、冲突事实、历史续报。
这是内部试验样本目标，不是正式 DCP 样本量。S0 清点覆盖不足的层并补标，不用重复材料凑数。
保留独立留出事件，不用同一批样本同时调参数和宣布改进。S0 探索集允许调参，S1 留出集只验收；
查看留出结果后若修改策略/阈值，重新冻结版本并使用未查看的留出事件，不用旧留出集再宣称独立收益。

输入快照、asOf、模型、选择窗口和预算固定；归组/提取策略按实验臂明确版本化，比较以下消融：

| 实验臂 | 固定项与唯一变化 | 应证明什么 |
|---|---|---|
| A | 现版选择与展示 | 共同基线 |
| B0 | 与 A 完全相同的已展示事实集合，只改变归组/排版 | 理解、定位限定/证据或阅读时间收益；维度覆盖应保持，不强求增加 |
| B1 | 与 A 相同的合格候选事实池，改变事件内事实选择并编排 | 释放此前被单代表规则挡住的互补事实；同时保住全刊重要事件覆盖 |
| C1 | 实际选定的 B 基线加首次互补提取策略 | 首次提取的正确重要信息增量及代价 |
| C2 | C1 加至多一次额外补提取；若未采用 C1，明确使用的 B 基线 | 额外调用本身的正确重要信息增量，不能借用首次提取或编排收益 |

B0/B1 是离线消融，不要求维护两条生产产品线。各臂盲序展示，逐事件和整刊分别评分。
阅读材料在发送前固化逐字文本、事实成员及哈希；若因界面问题重发，须使用同一版本并记录每次曝光。
重发时删改了事实细节的样本只能用于探索反馈，不纳入“只改变归组/排版”的配对比较。
某分层的 A 成品没有可归组的多事实样本时，B0 记为“不适用/无样本”，不得人为补入事实制造收益，
也不得据此自动否决 B1/C；各切片按适用样本及自身预登记门分别判定。
以同一候选事件全集预先标注必须覆盖的关键事件/重要维度，固定理解题及权重；
未发布事件计作遗漏，不能按每版幸存事件缩小分母。所有臂保持相同全刊阅读预算，单事实重要事件也进入非劣门。
私有原文与报告只留受控目录，版本库保存合成反例、协议及聚合结果。
旧 legacy 报告只能用于阅读对照；不能把未重新通过当前审计的历史事实输入新发布路径。

### 指标定义

| 指标 | 分母与用途 |
|---|---|
| 信息维度覆盖率 | 已正确表达的适用信息维度 / 人工从源文标注的适用维度；重点比较多事实子集，并同时报总体 |
| 全刊关键事件/维度召回 | 已正确覆盖的关键事件/重要维度 / 固定候选全集中预标注的关键事件/重要维度；遗漏计零，按主题和单/多事实分层 |
| 有效事实数 / 事件 | 非重复、通过校验且人工确认互补的事实数 / 发布事件数；保留单事实分层，不能靠拆句提高 |
| 错误归组率 | 含跨事件/版本错并的组 / 所有多成员组；同时报告应归组事件的召回，避免全部不归组得到假好分 |
| 证据覆盖与限定完整性 | 有正确绑定的断言 / 所有展示断言；正确保留必要限定的事实 / 需要限定的事实 |
| 历史重复率 | 无实质新信息的续报事件 / 所有续报事件；另报同源新增事实的漏报 |
| 阅读体验 | 盲评偏好、事件理解问题答对率、全刊阅读时间；区分“缺基本信息而打开原文”和主动深挖 |
| 运行代价 | 同输入每 topic 的额外调用、输入/输出 token、耗时和完成率；未知 USD 定价保持 unknown |

明确安全门：留出验收集错误归组、未绑定事实和条件丢失均为 0；所有发布事实保持现有白名单，
display/quote-only 安全评测 `unsafe_accept=0`。这些样本零错误不代表总体零风险。
收益门：B0 的事实覆盖不降低，理解正确率/查证效率/阅读时间的预登记主指标改善；
B1 在可编排子集新增正确重要维度；所有候选保持固定全集上的关键事件召回、重要维度覆盖及整体理解非劣。
C1 必须相对实际选定的 B、C2 必须相对其输入基线产生新增正确重要信息，并满足额外资源预算；
仅优于 A 不足以启用补提取。C 还须保持相对 A 的端到端安全和阅读门，未达到增量门则相应提取模式关闭。
最低收益幅度、阅读/资源上限、稳定运行次数在 S0 基于初测预登记，冻结后不得按结果降低门槛；
不达标就保持当前默认路径。字数和引用数仅作诊断，不作主要成功标准。

## 6. 验收场景

- [ ] AC1：同事件的三个合格互补事实形成一条消息、三个独立绑定；删除任一引用时对应事实不能继续发布。
- [ ] AC2：同一聚合文章中的两个不同事件不合并；同主体不同版本、日期或比较条件不混用。
- [ ] AC3：相同事实出现两次只展示一次；同事件不同事实保留；不得混合 occurrence 的引用来放行代表项。
  相同事实的较低排名 occurrence 若是唯一近期/新增合格证据，必须能成为最终代表，不能被预去重误删。
- [ ] AC4：带“仅在/最高/据来源报告”等必要限定的事实完整保留；成员失败后剩余句子仍各自自足。
- [ ] AC5：同文章的实质新事实可按新规则参与更新；旧事实改措辞、换 span 或换引用不得冒充新进展。
- [ ] AC6：旧历史缺失事实身份时保守兼容；新鲜度、14 天历史、至多两条补充发现及全刊规模限制均不被分组绕过。
- [ ] AC7：正文、标题、卡片、索引、通知和导出的声明均来自同一已发布成员投影；引用编号唯一、锚点可达。
- [ ] AC8：报告列出成员事实总量、事件总量和展示引用总量；薄日报告警与选择漏斗保持各自明确单位，不误报组合为减产。
- [ ] AC9：缺少成员证据包、审计、绑定或 artifact 清单时，正常/恢复提交均不产生新格式 done 报告；
  同 report ID/effect 的重试不重复提交。显式新尝试身份单独记录；不承诺跨渠道 exactly-once，未知投递结果不由新功能自动重发。
- [ ] AC10：来源更新、删除/redaction、恢复与 replay 后仍遵守既有访问边界；任何新旁路正文/快照同步受控。
- [ ] AC11：补提取超时、拒绝、无新增事实、取消和预算耗尽均有记录；可保留原已验证消息，无无界或完成终态重试。
- [ ] AC12：来源实际只有一个事实时生成简讯，不为了达到 2–4 句凑数；没有来源说明的影响不得生成“意义”段。
- [ ] AC13：模式关闭时生产选择等价；影子模式不写发布历史、业务去重基线或发送通知；隔离的影子产物不被读者索引读取。
- [ ] AC14：S0 冻结的分层质量、各臂增量、固定全集全刊非劣、阅读时间和资源门通过；模型 A/B 使用相同新契约单独报告。
- [ ] AC15：互补首次提取/额外补提取策略只对显式启用的 Brief 生效；非 Brief、off→on→off、冷/热缓存均无跨策略污染。
- [ ] AC16：发布后修改 live 来源/事实/引用/检查及当前选择策略，不改变任一展示面的固化证据；
  撤回后恢复旧数据库/文件、回放 registry，所有新材料入口仍执行撤回与权限策略。
- [ ] AC17：首次 on 前具备 off/shadow、隔离、最低兼容镜像、按 topic 停用和 on→off→on 历史连续性证据。

## 7. 灰度、回退与观察

拟将编排设置为 `off/shadow/on`，提取策略独立默认基线模式；名称和配置接线在实现 PR 中定稿。
S2 交付 off/shadow，S3 首次 on 前交付按 topic 控制及停用操作，S4 同时交付各提取模式的开关。
影子路径使用隔离快照/输出目录，不共享 live SQLite，禁止复用正常报告推送副作用。
先在一个 topic 验收新生成日报，再按 S0 冻结的完整运行次数扩至三个主题。

遇到错误归组、失去限定、引用不可达、绑定不一致或预算越界，关闭对应新路径并保留诊断。
回退只改变未来生成：旧路径必须继续认识新格式已经发布的全部成员事实，避免回退后再次推送；
新格式的已发布 artifact 仍按固化版本读取，不能动态拆回旧报告。不做降级 schema 或重写历史正文。
首次新格式发布前记录最低兼容镜像：至少支持新格式读取、证据包访问控制及全部成员的历史识别。
模式回退是在该兼容镜像上关闭新生成策略，不等于任意更早镜像可回退；镜像回退不得低于此兼容下限。

上线按既有 feature branch → review → PR → CI 流程；核验实际镜像和运行版本，
code-only 部署保留生产配置，避开 16:50–17:30 UTC 管线窗口。
观察归组/回退数、事实维度覆盖、成员审计淘汰、补提取收益、事件/事实/引用数、token 和耗时，
新增指标登记受控白名单，不输出原文、prompt、个人信息或密钥。
