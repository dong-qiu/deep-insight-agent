# C1 / TD-09：历史缺口处置与分层恢复验收

日期：2026-10-02。状态：方案与反例测试阶段；不授权生产恢复、路径迁移或历史重校验。

## 边界与处置

负责人确认没有其他已知旧主机、离线盘或云账户备份。本轮搜索结束，结论为“已知存储未找到更多原件”，不是“永久不可恢复”。未来出现新备份时只重启受影响项目的鉴别。本方案落实 ADR-0038 的当前证据/历史记录分离，不增加数据库状态枚举、许可体系或发布层级。

| 对象 | 本阶段处置 | 禁止 |
| --- | --- | --- |
| 初始 1,802 个 raw 候选 | 沿用私有封存清单；1,799 个正文一致、3 个仅替代处理顺序一致的差异仍单列 | 改写清单、补造生成时哈希、自动回填 raw_ref |
| 4 个新增 raw 候选 | 单独登记内容一致，保留人工归档及版本/哈希定位证据 | 并入原批次后复用其哈希、宣称历史字节已认证 |
| 4 份报告候选（8 文件） | 保留；两份历史计数差异单列 | 按现时规则重生成、改变历史 CitationCheck |
| 387 个规范路径缺文件、6 个空引用、10 份缺失报告 | 保留既有记录和不可用提示；固定已知搜索边界 | 删除引用换取完整备份、重抓网页冒充历史归档 |

四个新增候选仍属于 387 个缺文件项目；未恢复，不能减去四。当前图谱/线索继续经过现有 reader 证据门，不因候选存在而放行。历史报告正文、引用摘录、历史校验记录保留原样；归档不可用提示说明来源链接不能替代生成时原文，历史通过不表示按当前网页重校验。缺报告文件的记录不得用候选或新模板伪装成原件。本切片不修改读侧，若核对发现现有提示缺陷，另立受评审的修复。

## 分层验收：证据范围，不是放行开关

1. **机制**：真实脚本备份 raw/report/DB、封存哈希和全量引用，分别记录备份与异地传输能力。
2. **新格式数据能力**：完全合成的新格式引用/原文字节，走真实备份→隔离复制→真实校验。后续近期生产只读观察只能称指定范围观察，不得删去生产历史引用来生成“完整备份”。
3. **全量生产恢复**：含历史缺口的实际快照继续 `complete=false`，不得引入 `ignore_legacy`、`allow_partial_restore` 或历史 allowlist。

第 1/2 层通过不意味着 TD-09 完成；原“完整恢复点”验收保留。候选保全沿用已确认的版本化规则，不修改生产桶生命周期、不新增全版本 90 天删除硬门。恢复快照自身的 90 天窗口、身份安全与脱敏登记册回放要求不变。

## 验收用例

| 编号 | 输入/操作 | 预期 | 自动证据 |
| --- | --- | --- | --- |
| H01 | 合成新格式原文/报告经真实脚本备份并隔离复制 | 完整性通过，仅证明合成范围 | backup-integrity 的 default backup 测试 |
| H02 | 新格式可用引用与旧路径混在同一快照 | 新项可定位，整体 incomplete | mixed current/legacy 测试 |
| H03 | 复制同名旧候选并重新封存本次文件哈希 | 仍 unmapped，不自动认证/迁移 | candidate copy 测试 |
| H04 | 不完整清单人为声明 complete | 实际引用门仍拒绝 | declaration override 测试 |
| H05 | 核验含历史缺文件的快照 | incomplete；DB/报告字节及历史校验行不变 | historical record preservation 测试 |
| H06 | 候选内容一致或仅替代顺序一致；日期未知 | 历史字节仍 unproven；未知日期不算完整匹配 | c1-candidate-audit 对应反例 |
| H07 | 当前引用归档缺失/损坏 | reader 拒绝；历史记录不是放行旁路 | reader-evidence missing/corrupted 测试 |
| H08 | 查看缺归档的历史报告 | 正文保留且显示不可用提示，不写回/重校验 | 待下一切片人工复核；本次只确认提示代码存在 |

H01–H07 走现有生产等价函数/脚本，不另建判定器。H08 为人工要求，备份测试或旧的文件盘点不能代替 UI 验收。本阶段无 UI 变更；已静态确认报告页面提示代码，并复跑 report-archive-gap 的后端计数测试，但不宣称新浏览器验收或全量页面符合预期。

## 顺序与停止点

1. 固定搜索结论与本方案，补 H02–H05 反例并复跑 H01/H06/H07，独立评审。
2. PR/CI 通过后作为阶段记录合入，不关闭 TD-09、不部署、不恢复生产。
3. 下一切片先做**合成数据的隔离服务恢复演练**，按运维手册验身份、健康、业务读取和登记册拒绝/回放边界。不得删改真实生产快照制造通过；实际生产快照恢复另需明确目标/权限及登记册访问。
4. 分别报告“机制通过／合成能力通过／生产完整恢复未通过”。缺历史凭据/文件时停在这里，不无限重搜，也不改称 TD-09 全部完成。
