# Spec: 可溯源技术线索 (Technical Leads)

> V1 · 状态：✅ 已实现 · 2026-07-23

## 目标

把已校验洞察投影成可持续追踪的技术对象（模型、框架、论文、基准、工具、方法或安全模式），让用户看到“下一步值得关注什么”，同时不创建绕过引用校验的推荐旁路。

## 输入 / 输出契约

| 项 | 说明 |
|---|---|
| 输入 | `AnalysisBatch`、`ValidationResult`、`ContentItem` 元数据、既有线索历史与用户状态 |
| 输出 | `TechLead` + `TechLeadEvidence[]`；每条证据精确指向一条成功校验的 `Citation` |
| 触发 | 每个主题完成 validate 后，在报告生成前同步派生；不在纯采集 cron 中直接推荐 |

## 行为规约

1. V1 仅从同时满足“技术信号准入”（模型、框架、论文、评测、工具、方法或安全）与 `verdict=pass` 的引用派生线索；`flagged`、`blocked`、无校验引用及纯融资/IPO/政策动态不能自动推荐。
2. 线索标题优先取洞察 `headline`，缺失时取 `statement`；推荐理由由确定性字段模板生成，不新增 LLM 事实表述。
3. `canonical_key` 由主题 + 标题/首实体的规范化键构成；同键出现新成功校验证据时更新既有线索，不新建重复卡片。
4. 评分由近期性、成功校验证据的独立来源数、洞察重要性和主题相关标签确定；`score_detail` 必须可解释，用户反馈不改变证据或分数。
5. 自动推荐只展示最近 48 小时内有成功校验证据的线索；无合格线索时诚实显示空状态。
6. 单源线索仅推荐“关注”，多源且重要性高的线索可推荐“深挖”；用户的忽略状态不改变证据真值，并从默认推荐中排除。
7. 线索动作包括 `watching`、`dismissed`，动作写审计日志；“查看主题并深挖”复用既有受 admin 保护的主题深挖入口，不另造一条线索状态。

## 验收标准

- [x] AC1：每条推荐线索至少有关联一条 `pass` 引用，且点击可回原文 URL 与 quote。
- [x] AC2：同一 canonical key 无新增证据时不会重复创建；新证据追加到既有线索。
- [x] AC3：有近期合格证据时，推荐线索至少含一条该近期证据；无合格线索显示空状态。
- [x] AC4：评分、去重、状态迁移为确定性函数并有回归测试；生产路径验证从 validate 结果进入持久化和 API。
- [x] AC5：`dismissed` 线索不出现在默认推荐，`watching` 线索保留并可筛选。

## 非目标

- V1 不生成技术前景预测、采用结论或自由文本“为什么值得关注”。
- LLM 富化（技术简介、问题清单）需一周 dogfood 反馈及专用评测后另立 spec / Eval-Gate。
