# Daily Brief 信息完整性：新刊优先的加速交付切片

> 2026-10-03 · 基于用户“旧报告不补缺失信息、希望新 Brief 尽快上线”的范围调整草案；已按两轮独立产品/证据评审修订。本文不表示生产已获准。

## 结论与边界

原[实施规格](daily-brief-information-density.md)已经排除历史报告正文回填和旧 artifact 迁移，因此单独确认“不补旧报告”并不能省掉当前 S0 的大部分工作。可以缩短首发路径的是把**完整三主题优化**拆成一个**新刊单主题切片**：在有足够合格素材时，将同一新事件的 2–3 个互补事实呈现在一条消息中；来源只支持一项重要事实时继续短讯。拟先试“AI 时代的软件工程”，其余主题在试点后扩展。

现有诊断**不能证明这个切片已有足够素材**：唯一获产品确认的多项重要互补维度供给下界 E04 已出现在旧刊，不符合下述首发新事件范围。S0 须先在固定的新刊输入中量出通过全部门槛的同源新事件多事实机会；若不足，不能以 E04 或消息变长声称首发改善，应保持旧模式，并将有界首次提取实验提前为独立支线。

首发不重算、不补写、不重新渲染任何旧报告。旧报告仅供新刊继续执行现有保守历史去重；不把旧报告缺失的命题身份推断为“从未发布”。首发不启用跨来源归组、旧事件新增事实的事实级放行、补充发现成组、首次/额外补提取、模型或开源提取器替换。这些保持在后续完整方案中，不用它们阻塞首个新刊切片。

## 首发实现约束

1. 只处理本次输入中、同一冻结 `ContentItem` 版本、同一新事件的候选事实。每个事实分别通过展示审计、validator `pass/support`、新鲜度和原文/quote 绑定；不借一条合格事实放行另一条。事件归组需有可复核的主体、行动及版本依据；同 URL、同实体或相同 `event_id` 单独都不构成通过，不同 `event_id` 也不自动证明是不同事件。归组或语义去重不确定时沿用原短讯代表项。现有字面相同 statement/quote 去重不等于语义同义去重。
2. 现有同批选择先按 `event_id` 折叠，必须在此前新增事实级候选筛选，记录每个未纳入成员的具体理由。历史门在近 14 天按事件/指纹及新来源证据判断，**不能证明一个事件从未发布**。快路径仅对可观察窗口内未发现同事件/指纹已刊的近期一手来源尝试成组；对该窗口的已发布成员再按主体、行动、版本/时间作有界跨来源语义复核。存在同命题、同家族疑义、缺可用历史材料或复核失败时，全组回退原选择并记录原因，不能靠新 URL 放行。首发不尝试放行“同文旧事件新事实”，也不声称全史新颖。每组最多 3 条，经人工确认的互补维度用于评测，不以引用数或句数代替。
3. 首发**必须**补齐新格式最小不可变 Story/成员证据包：最终文本及 hash、有序成员和归组/选择/renderer 版本、各成员的唯一主引用、逐字 quote 与 locator/有界 span、来源版本及受控归档绑定、完整展示审计和 validator 检查。正常保存与恢复提交共用版本化 guard，核对 Markdown/HTML artifact hash 与成员清单；引用一致性不能退化为当前行可达或 quote 子串可见。复用现有 `insight_ids`、发布决定和 artifact 的可用部分，但现有 revision/恢复检查缺口已确认，不能把补齐成员包设为可选。删除/redaction、恢复及重试均需覆盖新增材料。
4. Markdown、HTML、预览、卡片、索引、通知与 PPT/导出必须从同一固化发布投影读取，引用编号和组成员一致。若 PPT/导出无法在首发前支持新格式，则应显式禁用相应新格式入口并验证不会输出另一套事实；不能从可变 batch 重算选择。
5. 使用默认关闭、按主题开启的新刊开关。离线及影子运行在隔离 DB/目录中，不能写生产发布历史或发送通知。上线只开启软件工程主题；需记录支持新格式读取及成员历史识别的最低兼容镜像，并完成 on→off→on 回归。出现错并、失去必要限定、无证据成员或历史重复，关闭新生成路径，已发布 artifact 保持原样。

## 缩短的验收路径

| 环节 | 首发需要 | 后续完整方案继续做 |
|---|---|---|
| S0 | 在固定软件工程主题新刊窗口清点实际可发布的同源新事件多维度机会；冻结来源家族独立留出、适用多事实样本/完整运行下限、A/B0/B1 各自门槛、全刊阅读和事实预算、失败/无刊/重试计分以及绝对完成与覆盖下限。记录旧日志不可恢复项为 `unknown` | 三主题均衡留出、所有来源形态和完整历史供给估计 |
| S1 | 用未参与调参的前瞻窗口和固定完整输入分母分别比较 A/B0/B1；逐组人工查错并、漏并、事实互补性、限定、证据及全刊遗漏。B1 对与 A 相同的合格候选池衡量正确重要维度增量；B0 仅在有适用样本时单独衡量阅读收益，无样本记 N/A 而不否决 B1。固定全集的关键事件与重要维度覆盖、完成率和阅读预算须达到预登记非劣/绝对门。B1 没有足量适用样本则不能批准 on | 三主题消融及 C1/C2 提取和模型/开源工具增量比较 |
| 实现/上线 | 交付成员证据包与共同 guard、选择和固化投影、全展示面或明确禁用、off/shadow/on、生产路径回归；独立评审及 CI 后仅对一个主题启用并人工验收新刊 | 跨来源、旧事件事实级续报、补提取、三主题推广和稳定性观察 |

首发安全门保持零容忍：已检查样本中错并、无合格证据事实、必要限定丢失为 0；发布白名单不得降级为仅检查网页可达。收益门不以篇幅或引用数代替。S0 必须先将现有“每条 ≤120 字”、每刊条数上限与新刊阅读预算的关系写成明确版本化修订；不增加最低字数，也不按长度截断必要限定。若前瞻窗口没有足够可编排素材，诚实记为“不适用/收益未证”，保持旧模式；不能为了赶进度补写未支持细节。

此切片仍按 feature branch → review → PR → CI → 合并，再验证实际部署版本。S0 草稿 PR 与后续实现 PR 保持分开；首发上线不等于完整实施规格已完成。
