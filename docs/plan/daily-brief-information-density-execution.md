## 1. 交付顺序及职责

先完成 S0/S1，拿到真实证据再选择生产实现。S2/S3 交付事件编排；S4 的离线试验可提前，
生产提取策略须等 S2/S3 绑定和展示能力完成。没有收益的实验臂不进入生产。

| 工作包 | 任务 | 依赖 | 可提交的交付物 |
|---|---|---|---|
| PR-1 / S0 | T01–T04：环境、取样、标注、冻结协议 | 无 | 只读导出器、合成测试、聚合诊断、实验协议及标注模板 |

PR-3、PR-5 拆成小 PR 是对原六阶段的工程细分，不新增功能范围。
每个 PR 合并前独立 review，引用对应任务、AC、测试/评测证据；不把“前一 PR 已通过”当后续行为已验证。

职责：实现者维护代码、样本协议和证据；产品维护者完成源文信息维度/阅读效果的人工确认；
独立评审检查语义与代码边界；发布执行者按既有流程执行实际启用。AI 预标注不能记成人工盲评。
可并行进行的工作是代码/证据盘点与标注准备、离线提取可行性与编排试排；
不得在实验结论之前并行铺开生产 schema、prompt 和所有展示面的改造。

2. 实验 SQLite 使用已有一致性快照或 seed 的独立副本，显式绝对路径；不得直接挂 live DB。

### T02 — 导出候选全集并定位事实损失

> 以下完成条件已于 2026-10-03 获产品维护者明确采纳，决议与证据边界见
> [T02 验收边界记录](../verify/daily-brief-density-t02-boundary-proposal.md)。修订后的有界历史诊断门
> 已按[逐项复核记录](../verify/daily-brief-density-t02-gate-review-2026-10-03.md)签认；这不是完整历史供给数、
> S1 全刊收益验收或 S0 合并许可，T03/T04 仍未完成。

拟新增 `evals/brief-density/export.ts`。参考 `evals/export-qualified-tech-leads-v2.ts`
的显式绝对路径、`readonly: true`、`fileMustExist: true`、单读事务与独占输出方式。
禁止导入会 bootstrap/migrate/reconcile 的 `getDb/openDb` 作为只读导出入口。

1. 先以此前审计的 2026-09-23～26 日、三个主题作为候选窗口；不足时按固定日期规则扩展并记录原因。
2. 取所选输入文章、分析候选审计、保留 Insight/Citation/check、报告选择记录、发布成员及原文归档绑定，
   **不只导出已经发布的消息**。对同批次候选给出互斥终态桶和可解释的阶段计数。
3. 对照源文逐项判定信息损失位置：源文没有、提取未产出、展示审计拒绝、validator 拒绝、
   新鲜度/历史过滤、事件代表项折叠、最终显示。旧系统没有记录的部分标为 unknown，不能补造候选文本。
4. 校验归档内容 hash/版本和 quote locator；只有 live 行、缺原文快照或审计链的样本标记证据缺失。
   证据缺失单独报告，不悄悄剔除后把剩余样本当完整总体，也不能送入候选发布池。

**私有输出**：`snapshot-manifest.json`、`candidate-pool.jsonl`、`stage-loss.json`；
manifest 保存输入 hash、asOf、topic、窗口、软件/策略版本、证据完整度，不保存凭据。
**完成（历史可观测诊断）**：快照 DB SHA、可审计的备份时间区间及逻辑 `asOf` 先建立可信绑定；
固定窗口的三主题输入、可观测候选、互斥终态、阶段损失与证据缺口均可追溯；
对有候选级来源及引用绑定、通过既有机器门且可恢复的事实，
只报告以人工确认的重要维度为参照、经独立语义复核及产品逐项确认的互补供给下界；当前 E04 的有界下界已获确认，
不是候选发布批准或事实金标。
旧系统未保存的候选文本、候选级来源归属或无 batch 尝试总数保持 `unknown`，不得计零、补造，
也不得把已审子集外推为完整历史事件供给数。T02 的这项完成条件不等于信息完整性收益或 S1 全刊验收通过。
备份清单在 SQLite 文件生成后才写入时，清单 `created_at` 只能证明清单时间；
导出器两项时间参数相等，不能代替快照捕获证据。

**转入 S1 的全刊验收约束**：用 T04 预登记的前瞻固定输入窗口检验完整全刊召回和非劣；
固定全部输入和事件/维度金标，保留逐候选来源版本、受控原文归档、逐字 quote/locator、
展示审计、validator 结果及失败尝试。证据缺失单列，不能进入合格事实池或从固定分母中悄悄剔除。
未发布的重要事件及运行失败仍计入固定分母，失败原因另报；无刊、部分刊、重试和绝对完成/覆盖门
须在 T04 预登记，不能仅凭各臂同时失败时的相对非劣宣布通过。前瞻结果不能回填为旧窗口的历史事实。

### T03 — 标注事件、事实和固定问题

1. 建议起始集至少 30 个事件、每主题至少 10 个；把单事实重要事件和失败/未发布候选纳入抽样。
2. 私有标注表字段：`event_key`、`topic`、`source_revision`、`event_family`、是否关键事件、
   适用信息维度、各维度的事实/证据 span、必要限定、可接受的归组、历史是否已报、固定理解题及答案。
3. 将同一事件家族、转载/近重复文章、版本续报整体分到同一分区，防同源事实泄漏到探索集和留出集两侧。
   探索/留出比例与各层最小例数在 manifest 预登记，覆盖不足则补样本或标为不可评估。
4. 对数据包的源文分层作人工确认，分歧记录后裁定；重要事件与题目不能根据候选报告表现事后改写。

**完成**：源文可支持的信息维度、事件归属、必要限定、固定题目和分区都有可追溯标签；
没有真实读者回填时结果保持 pending，不用 AI 自评分声称阅读收益。

**完成**：协议数值不含占位符；探索集可继续用于开发，留出标签封存；旧 report-generation/去重规格中
需要替换的条款列明。S0 接受实验边界，ADR-0036 仍不以“评审同意”冒充上线决定。

### T06 — 验证自动归组、事实历史及提取潜力

1. 先试严格同 topic/content revision 的候选筛选，明确同文章/实体/event_id 不是归组通过条件。
2. 将分组规则或有界语义复核输出与人工标签比较，计错误归组、召回、调用量和 unknown 回退率；
   将命题新颖性作为单独任务评测，不把归组通过当作新事实通过。
3. 所有疑义保持单独简讯或保守不重报；模型只能给候选决定，代码检查成员白名单、版本、来源及预算。
4. 若供给不足，可在同一隔离输入上提前运行 C1/C2 可行性试验；首次 prompt 改动和额外调用分开记账，
   新事实经过完整审计与 validator。此处只做离线执行，不提前迁移生产缓存/重试/表结构。

**完成**：形成版本化策略和决策表，而非只有“模型判断同事件”一句描述；哪些自动规则可用、
哪些分层不能可靠判定都有结论。涉及模型/数据集语义时按 eval-gate 留真实安全评测证据。

### T07 — 留出验收并选择路线

记录实际通过/失败/不可评估，并按下表决定后续：

| 结果 | 后续动作 |
|---|---|
| B0 阅读获益，B1 没有额外覆盖收益 | 仅交付必要编排与绑定，不为凑范围上线更复杂选择策略 |

### T10 — 实现事实历史与新选择器

建议将独立规则放入 `src/lib/agents/brief-story.ts`，`report-gen.ts` 负责接线，避免把全部逻辑塞进渲染函数。

1. 在 `listRecentPublishedInsightOccurrences` 相邻读模型中提供新版命题发布记录，保留 legacy occurrence 读取。
2. 按冻结决策表先标候选重复/事件组，不提前删 occurrence；逐成员应用新鲜度和历史判定，再选代表和最终组。
3. 不把 fetched_at、quote hash、source revision 改变直接当成新命题；疑似同义复述走有界策略。
4. 组内预算、全刊预算、两个补充发现上限分别执行；标题只复用合格事实，缺分组依据回退简讯。
5. 输出单一 selection object：成员顺序、story 映射、引用、排除原因及计数，供持久化和所有渲染共同使用。

**完成**：通过同文新事实/仅换证据/legacy+new/旧背景/单代表误删等反例；
低排名 occurrence 是唯一新鲜证据时仍可胜出；S2 有语义调用就同时执行定向语义评测。
