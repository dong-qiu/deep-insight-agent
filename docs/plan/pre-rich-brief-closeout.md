## 2. 完成 S0/T03：来源家族与标注分区

沿用 T01 隔离环境和已签认的 T02 有界诊断，不重开已完成的历史原件搜索。31 份源文/30 个事件的人工标签保留；其余原窗口来源首筛只作候选，不自动升为事实金标。

3. 核对同研究、同节目、转载/镜像、版本续报及已刊历史，将家族整体放在探索或留出一侧。已在 10 月 3～5 日运行中被查看的来源只能留探索；新的正式留出必须在 T04 冻结后从未见的前瞻家族封存。对未归档网页、只含摘要/节目简介的材料标明正文形态和证据缺口。

1. 在探索材料上先按事实等价生成 A/B0/B1 盲序阅读包，固定逐字文本、事实成员、hash 和曝光记录；删改细节的重贴样本仅作探索反馈。补齐必要的真实阅读题回填，不能将用户对不等事实版本的阅读时间并作配对结果。
2. 在 `docs/verify/daily-brief-density-experiment-protocol.md` 冻结可执行的数值：B0 阅读收益门、B1 重要维度增量及全刊关键事件非劣/绝对覆盖门、适用多事实样本下限、整刊时间/事实/事件预算、连续运行数、成本/token/超时上限。只有来源确实支持一项事实时允许短讯，不设最低字数。

4. 冻结模型/provider/prompt/cache 版本及历史判别、证据字段缺口、命题 identity／证据 occurrence／报告成员三层决策表。列出旧 `report-generation` 的 ≤120 字和单代表项等条款何时由将来的上线切片版本化替换；当前报告行为不在 T04 改动。
5. 封存**未用于调参**的前瞻来源家族、样本量与开启窗口。若探索材料不足以负责任地给出数值，明确缺哪一层、可补的固定窗口及最迟停止点；不得填占位符或把已看来源称盲测。是否将 PR #360 改为“诊断成果合入、T04 仍未完成”的较窄范围，必须先单独修订 S0 完成门并记录用户决定，不能自行按原完成门宣布通过。

**交付/完成**：协议全文无占位数值、manifest/hash/版本绑定，两个设计表闭合，独立 reviewer 可按同一输入复算分母和 go/no-go；留出集未泄漏。S0 的成功仅表示可进入 S1 实验，不表示新格式可生产发布。

## 6. 审核并清理已合入的本地 worktree/分支

1. 在最新 `main` CI 与**需要的部署核验**完成后重新运行 `npm run branches:cleanup` 默认 dry-run，记录 PR、merged head SHA、本地分支 SHA、worktree 干净/锁定状态；将三个排除的重构分支及当前/主 worktree 从候选中剔除。
2. 不直接用 `npm run branches:cleanup -- --apply`：当前脚本预演会包含被排除的 D2，而且实现以 `git branch -D` 删除分支。此轮只在逐项确认后移除干净、未锁定且非当前/主 worktree；再使用非强制 `git branch -d`。若 squash merge 使 `-d` 拒绝，留下分支并记录原因，不把 `--force` 当日常清理手段。
3. 对本地尚无 merged PR 的 S0、提取试验和主工作区旧方案分支，先按前五项归档/合入或保留；未提交、未跟踪、私有数据和排除的重构 worktree 不做删除。远端短生命周期 head 的删除由 GitHub 仓库设置处理，本轮不手动删除远端分支。

**交付/完成**：一份最终候选/已清理/保留清单，所有已清理项都满足合入头未推进、worktree 干净未锁、CI/所需部署核验通过；保留项有明确理由，无资料丢失。
